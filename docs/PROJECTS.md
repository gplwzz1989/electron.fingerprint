# 独立项目边界

| 项目 | 所有权与职责 | 对外依赖 |
| --- | --- | --- |
| `fingerprint-browser` | 通用桌面基座：标签、权限、环境、代理、参数执行、本地接口、更新 | 已有自定义 Electron 运行时；第三方首页及公开协议 |
| `saas-server` | SaaS 网页、认证、团队、指纹生成、MySQL、支付与业务 SDK | MySQL、SMTP、部署配置的外部业务服务 |
| `integration-tests/saas-desktop` | 显式同时提供双方发布物的联调验收 | 两个独立项目的路径，仅用于验收，不随产品发布 |
| `docs/product-design` | 历史画册、交互稿和研究资料 | 不参与任何项目构建 |

两个项目各自具有 package.json、配置样例、忽略规则、测试和打包脚本，可单独导出到不同仓库。禁止相互 require/import、file/link/workspace 依赖、符号链接、构建时复制对方源码、读取对方配置或从父级源码目录查找依赖。

服务端所有运行模块归本项目 `src/` 管理；基座不内置该 SaaS 的 Cookie 名、认证流程、HTTP 业务地址或数据模型。相互通信只通过公开的版本化桥接和加密 JSON 契约。协议两端保有独立实现；修改任一端不得自动重写另一端。

独立交付：分别在两个目录执行 `npm run package:source`。SaaS 执行自身 `scripts/package-deploy.ps1` 生成部署包；基座执行自身打包脚本并显式提供已有运行时，不进行原生编译。

现有原生源码、工具链及构建缓存保持原位置，属于运行时工程，不能被应用项目整理或独立导出脚本删除、搬移、清理或重建。
