# 指纹浏览器商业 SaaS 开发计划

评审稿：2026-10-03。依据：当前仓库源码、已有开发与发布记录、六款竞品官方公开资料。

本次交付为产品规划和高保真设计，不代表已经实现团队、代理、云同步、支付或 macOS 运行时。设计中的名称“栖界”、团队、数据、套餐价格均为暂定或演示。现有代码及历史开发计划保持不变。

## 1. 产品决策

建议定位为“面向团队的独立浏览器环境工作空间”：让用户稳定打开业务环境、明确知道谁能访问、数据保存在哪里、异常如何恢复。先以 Windows x64、macOS Intel x64、macOS Apple Silicon arm64 三平台交付，Windows arm64 暂不列入首版范围。

首批客群暂按 3—20 人的跨境电商与营销团队制定；这是待验证假设，不是已完成访谈的结论。个人用户可作为体验入口，中大型企业需求放在后续。主任务是创建环境、配置代理、持续使用、交接给同事、处理异常和购买合适配额。

产品价值优先级：登录与数据可靠性 > 网络与运行隔离 > 多平台稳定性 > 团队协作 > 使用效率 > 自动化广度。不要把参数数量、指纹检测站分数或“永不封号”作为核心卖点。

商业化采用桌面客户端执行浏览器工作、云端提供组织与订阅控制。首版不自建云浏览器集群、不做云手机、不开发可视化自动化编辑器、不内置代理交易市场。云同步作为明确选择的服务，不能为了订阅默认上传 Cookie。

### 一个必须先解决的产品模型

当前每个网页标签独立 Session，适合验证隔离，却不利于同一店铺同时打开订单、后台和帮助页。目标模型为：

- 模板：用于创建环境的指纹默认值；模板更新不改变既有环境。
- 环境：业务与权限的基本单位，持有稳定指纹快照、独立目录和 Session。
- 网页标签：属于环境；同一环境内共享会话，不同环境之间隔离。
- 首版优先一个环境一个浏览器窗口，窗口内多网页标签；跨环境标签合并后置。
- 旧版每个标签环境原样迁移为一个环境，不自动合并目录或 Cookie；用户只能显式选择后续组织方式。

不要按竞品首页认定“Mac 支持”必然等于原生 arm64。AdsPower、GoLogin、比特的官方页面本次能明确看到两种 Mac 下载项；其他产品的具体架构、签名和运行限制需另外核验。

### 核心差异化

1. 每个环境的运行、代理、同步、占用、最近检测时间可见，异常有明确下一步。
2. 新建默认走三步业务流程；高级参数保持可查看，但不成为首次使用门槛。
3. Windows 与两种 Mac 的真实能力分开检测，不能仅改 UA 或平台字符串就声称跨系统一致。
4. 团队成员只获得获授权环境；导出 Cookie、转移所有权、管理成员、查看计费为独立高权限能力。
5. 环境状态、配置修订和同步版本透明，交接不能覆盖另一台设备的更新。

## 4. 用户研究与产品验证

本次没有真实用户访谈数据。商业开发第一周安排至少 3 个团队访谈：运营负责人、日常操作者、管理员，记录创建数量、每天切换次数、交接场景、代理采购、数据保留和支付习惯。

第二周请 5—8 位目标用户在高保真原型完成：创建首个环境、找到异常环境并处理、邀请成员并授权、关闭后交接、判断需要哪档套餐。先做导航查找验证，再做完整任务。记录完成率、任务时长、误操作和 SUS，设计目标为关键任务完成率 ≥90%、首次创建中位时长 ≤3 分钟、SUS ≥80；这是目标，不是实测结果。

若主要用户是个人工作室：减少团队首页与云同步投入，先验证本地付费意愿。若主要用户是企业：需要重新估算身份集成、私有化与审计需求，不直接套用本稿的 16 周估算。

## 5. 信息架构与关键流程

客户端一级导航：工作台、浏览器环境、代理资源、团队成员、操作记录、订阅与用量、设置。配置模板放在环境创建与设置中；任务自动化在具备稳定接口后再开放。

网页登录后台聚焦账号、组织、邀请、套餐、账单与审计；浏览器运行仍在桌面客户端，不把桌面外壳上传云端就称为云浏览器。移动端首版仅适配账号/账单等控制台，不支持桌面浏览器运行。

### 创建和日常运行

注册/登录 → 创建或加入工作空间 → 选择本地存储或启用云同步 → 新建环境 → 填业务名称与分组 → 绑定并检查代理 → 查看指纹推荐与一致性提示 → 创建 → 打开环境。

启动前检查：设备占用、目录可读、内核能力、代理连接、订阅与授权。代理断开不静默直连；需要用户明确选择并记录“使用本机网络”，启用代理的环境默认阻止启动。首次创建成功后显示“打开环境”“邀请同事”，不把高级参数当下一步。

### 团队交接

成员邀请 → 接受邀请 → 获得分组或环境授权 → 下载已提交版本 → 获取占用租约 → 运行 → 关闭并完成一致性备份 → 上传成功 → 释放交接状态。上传失败显示“本机已保存，团队版本未更新”，不得显示为已同步。

### 核心状态规格

| 维度 | 状态 | 用户界面要求 |
| --- | --- | --- |
| 运行 | 已关闭、检查中、启动中、运行中、关闭中、启动失败、恢复待确认 | 只有执行结果确定后切换状态；处理中禁重复点击；失败附中文原因与操作 |
| 代理 | 未设置、未检测、检查中、可用、连接失败、认证失败 | 显示检测时间；可用不等于永久可用；密码隐藏 |
| 同步 | 仅本地、待上传、同步中、已同步、同步失败、版本冲突 | 显示本地与远端版本；失败保留本地副本；冲突禁止静默覆盖 |
| 占用 | 未占用、本机占用、其他设备占用、租约失联 | 显示成员和设备；强制接管限管理员，须提示后果并留记录 |
| 数据 | 可用、目录丢失、备份可恢复、回收站、等待清理 | 恢复和删除分开；永久删除显示环境名称及数据影响 |
| 订阅 | 试用、有效、付款处理中、宽限、到期、配额超限 | 到期不删除本地数据；不结束已有窗口；新增与同步按明确规则限制 |

每页必须设计加载、空、无权限、无搜索结果和错误状态。保存表单失败保留输入；过期修订提供“重新载入并比较”，不能自动覆盖。

## 6. UI 改造计划

现有卡片列表在环境数量增加后不利于扫描，配置与环境并列也会混淆“编辑模板”和“恢复已有业务”。重构管理界面时保留数据与 Session 行为，先替换导航和环境列表，再接真实接口。

### 首批高保真页面

| 页面 | 主要内容 | 优先级与实现时点 |
| --- | --- | --- |
| 工作台 | 当前可执行任务、最近环境、需处理事项、首次使用引导 | P0，第 1—2 周设计 |
| 环境管理 | 表格、搜索、分组、标签、状态、负责人、批量操作、配额 | P0，第 3—4 周接本地数据 |
| 创建环境 | 基本信息、代理与地区、指纹推荐；摘要和验证反馈 | P0，第 3—6 周分步接入 |
| 环境详情 | 概览、访问权限、稳定指纹快照、同步版本、活动记录 | P0，第 5—10 周逐步完成 |
| 代理资源 | 检测、地区、延迟、绑定数、批量导入、认证异常 | P0，第 5—6 周 |
| 环境浏览器 | 环境归属、窗口内标签、地址栏、下载与权限入口 | P0，第 3—6 周 |
| 成员与授权 | 邀请状态、角色、分组范围、敏感操作权限 | P1，付费团队测试前完成 |
| 操作记录 | 操作者、设备、目标、结果、筛选和脱敏导出 | P1，第 9—12 周 |
| 订阅与用量 | 当前套餐、环境/席位/空间、账单、到期/超限处理 | P0，开始收费前完成 |
| 客户端设置 | 本机能力、存储、更新、诊断、键盘快捷键 | P0，第 5—8 周 |

视觉采用冷白主画布、深石墨导航、钴蓝主操作色、文本化状态标签。重心是紧凑可扫描的业务表格，不使用大面积渐变和装饰图占据操作区域。首版浅色主题优先，暗色版在组件令牌完成后追加，不同时维护两套独立样式。

详情用右侧抽屉保留列表上下文；新建采用独立页面，减少狭窄弹窗里塞满参数。危险操作使用专门确认对话框；启动失败的原因留在行和详情里，提示浮层只补充即时反馈。

### 交互与可访问性要求

- 正文 14px、辅助信息不小于 12px；默认行高 56px，紧凑模式 44px。
- 主导航 224px，内容间距 24—32px，按钮高度 36/40px，表单高度 40px。
- 表格数据多时采用服务端分页或游标；本地早期先分页，不为了未测量的性能引入虚拟化。
- 所有筛选可清除，状态不只靠颜色；批量操作显示选择数量及逐项失败结果。
- 键盘可导航、焦点可见；对话框管理焦点、支持 Escape 返回；错误通过可访问提示宣布。
- Ctrl/Cmd+K 搜索、Ctrl/Cmd+N 新建、Ctrl/Cmd+L 地址栏；不得覆盖常见网页快捷键。
- Windows 100/125/150% 和 macOS Retina 验证文字与命中区域，中文字体使用系统字体栈。
- 桌面工作区支持 1024×768 及以上；1280/1440/1920 为主要检查宽度。小屏导航收起，表格在自身区域滚动；320px 页仅作为控制台/原型降级，不承诺桌面客户端体验。

## 7. SaaS 与桌面架构

### 最小可行方案

继续沿用当前定制 Electron/Chromium 运行时，管理 UI 与网页内容的安全边界分离。管理 UI 可先用现有原生 HTML/CSS/JS 建立组件规范，不因设计升级立刻更换框架；当真实团队界面规模和状态复杂度证明有需要时，再评估 React 或 Vue，并独立安排迁移。

云端先采用模块化单体服务，处理身份、组织、授权、环境元数据、占用租约、同步清单、审计、订阅与权益。建议关系型数据库加对象存储；若团队已有数据库，优先评估复用。不要让渲染进程或第三方网页直接访问数据库。

本地短期保留现有 JSON 格式与可靠性处理；遇到多表查询、频繁批量更新与事务需求时评估 SQLite。迁移前备份，记录 schemaVersion 和迁移日志；数据版本向前升级，应用降级不自动读写不兼容数据。

客户端 → 可信主进程 → 云 API（元数据/权限）或本地运行服务（Session/代理）；网页视图保持无 Node、无应用通信桥、沙箱和 contextIsolation。IPC 校验发送者、对象字段、长度、URL 和路径，远程输入不能变成任意文件写入。

### 核心业务对象

| 对象 | 最小字段与规则 |
| --- | --- |
| 工作空间/成员 | workspaceId、userId、角色、邀请/停用状态；每条业务查询都受工作空间与授权限制 |
| 环境 | id、workspaceId、名称、分组、标签、来源模板 revision、不可变指纹快照、存储模式、修订 |
| 模板 | id、revision、能力要求、目标平台、经验证的参数组合；不热更新已打开环境 |
| 代理 | id、类型、主机、端口、加密凭据引用、最近检测结果；日志不含密码 |
| 设备/租约 | deviceId、environmentId、leaseId、到期时间、单调递增 fencingToken；旧持有者不能提交新版本 |
| 同步版本 | versionId、baseVersion、manifest、hash、大小、schemaVersion、kernelCompatibility；提交后不可变 |
| 权益/账单 | 套餐、周期、环境/席位/空间配额、支付状态、服务端权益版本；客户端不作为支付真相来源 |
| 审计 | 操作者、设备、操作、目标、时间、结果、请求 ID；内容脱敏，默认不记录浏览网页正文 |

### 角色模型

所有者：计费、转移所有权、全部配置。管理员：成员、分组授权、环境管理。操作者：仅授权环境的运行与业务操作。只读成员：查看获授权元数据，默认不能运行或读取凭据。

权限同时控制动作和对象范围，默认不允许导出 Cookie/凭据。隐藏按钮仅是界面反馈，服务端与可信运行服务必须再次校验。成员离职立即撤销令牌和后续操作；已复制到其设备的数据无法凭界面承诺远程彻底抹除，需明确这一限制。

## 8. 同步与安全的真实边界

首版必须先把本地工作做可靠，再开放云交接。环境目录不能在运行期间直接打包上传，也不能用“一份目录复制到另一个系统”替代同步设计。

1. 关闭网页视图并等待浏览器退出/静止后，刷新 Cookie 和相关存储，再生成一致性检查点；必要时重启前完整快照，确保 SQLite、LevelDB 等不会半写入。
2. 分阶段同步：元数据与指纹快照先支持跨设备；Cookie 通过受控导出/导入处理；其他存储与扩展目录按系统和内核兼容性白名单逐项验证。
3. Cookie/密码可能受 DPAPI、Keychain 或 Chromium 密钥格式保护，不能直接迁移加密数据库。用户密码与系统密钥不作为首版同步内容。
4. Windows 与 macOS 的持久存储兼容性、字体和 GPU 输出不能假定一致；不兼容环境明确阻止跨系统运行，提供同平台交接或重新创建。跨系统“无缝登录”需单独验收，不能作为 MVP 默认承诺。
5. 云同步启动前需选择上传范围和授权成员；传输用 TLS，服务端加密存储与租户隔离，客户端凭据入系统安全存储。首版只承诺已实现的加密方式，不声称端到端加密；如果未来采用端到端方案，另设计密钥分发、成员撤权、密钥轮转和恢复。
6. 获取租约后才能启动云共享环境；冲突保留两个版本，禁止自动合并 Cookie 数据库。心跳失联时本机保留工作，但不得覆盖云端；旧 fencingToken 的上传被拒绝。
7. 默认离线仅允许已授权的本地环境使用；共享云环境离线不能首次占用。离线运行期间不承诺立即撤权，须在产品说明中写清。
8. 对象上传先校验清单与校验和，再原子提交版本；断网可重试，旧版本不提前删除。备份与回收站保留期应随套餐清晰显示。

登录采用受支持的身份服务或现有组织身份实现，不自创密码学协议。提供 MFA、设备会话列表和远程退出；计费回调验签、去重并对账。诊断包默认不含 Cookie、代理密码或网页正文，由用户预览后导出。

## 9. 三平台交付计划

| 平台 | 首版建议范围 | 必须提供的证据 |
| --- | --- | --- |
| Windows x64 | Windows 10 22H2 / Windows 11；Windows 10 已结束常规支持，需结合 ESU/内核支持评估最终政策 | 干净系统安装、签名、代理/权限/恢复/升级、不同缩放与显卡、正常/崩溃退出 |
| macOS Intel x64 | 暂按 macOS 13+ 评估；最终下限取决于所选安全维护内核与实机覆盖 | 原生 x64 完整构建、签名、公证、staple、Gatekeeper、Intel GPU 与存储回归 |
| macOS Apple Silicon arm64 | 暂按 macOS 13+ 评估，提供原生 arm64 包 | M 系列实机运行且 process.arch=arm64；不能把 Rosetta 跑 x64 当 arm64 支持 |

先发两个 Mac 包，官网按芯片类型明确选择；Universal 合包只有在尺寸和升级收益明确后再做。Windows ARM、Linux、手机与云端浏览器暂后置。

### 平台工程事项

- 三种目标必须编译完整定制运行时，包含资源、ICU、V8 快照、语言包、FFmpeg、许可证；npm 官方 Electron 不能替换掉指纹内核。
- 所有原生模块和辅助二进制按目标 CPU 编译与签名；开发机器运行成功不能代替发行包测试。
- Mac 构建使用受支持 Xcode、SDK 和 macOS 宿主；编译资源、Intel/M 系列测试机、Developer ID 账号为外部前置条件。
- 签名覆盖主应用、Framework 与 Helper；Hardened Runtime 权限只启用必要项，完成公证及 staple 后验证下载文件的 quarantine/Gatekeeper 行为。
- Windows 使用代码签名与可信时间戳；首次安装下载信誉不等于签名失败，不用关闭系统防护来“解决”。
- 数据目录从项目 `.data` 演进为 app.getPath 对应系统路径；保留开发覆盖变量，支持旧数据迁移预览、确认、备份及失败恢复。
- 路径空格、中文、大小写、只读目录、网络盘、磁盘满、符号链接都要验证；不依赖 Windows 绝对路径和盘符。
- Chrome/Electron 老基线的安全更新为商业上线阻断项：先选择可维护的上游版本并移植补丁，三平台回归后上线；文档不能把 37.2.6 当长期安全策略。
- 更新先校验签名与产物清单，空闲时安装；浏览器环境运行中延期。客户端与内核/Schema 有兼容矩阵，灰度失败可回退程序但不倒退破坏数据。
- “MacIntel”是网页平台标识，Apple Silicon 浏览器也可能报告它；它不代表 CPU 架构，更不证明完整 Windows/Mac 指纹模板可信。

### 回归矩阵

三平台均覆盖：无指纹/模板 A/模板 B/模块关闭；页面、普通 Worker、ServiceWorker、跨域 iframe；请求 UA/Client Hints/语言；Canvas、Audio、字体、ClientRects、WebGL 与真实 WebRTC ICE；两个环境存储与代理隔离；环境内标签会话共享；授权弹窗、下载、权限、崩溃恢复、版本升级。

测试报告绑定产物 SHA-256、运行时版本、补丁清单、系统/CPU/GPU、检测时间和输入模板。指纹网站是辅助观察，不能代替独立探针，也不作为避免平台风控的保证。

## 11. 商业包装与运营

建议先采用低门槛体验、个人、团队、企业四层，但首期收费只做个人/团队。体验建议 5 环境、1 席位、明确 14 天试用；具体配额、期限、币种、含税价格需通过试点访谈与成本核算确定。原型里的 ¥99/¥299/¥899 等仅用于检验套餐布局，不能直接作为正式报价。

收费单位为工作空间月/年订阅，主要配额是环境数、成员席位和同步空间；本地并发由机器能力与套餐明示上限决定。代理流量、云手机与第三方成本不伪装为无限量权益。环境回收站占不占配额、邀请待接受是否占席位、到期可运行哪些环境都必须在定价页讲清。

试用结束/欠费：保留本地数据与导出能力，正在运行的环境可安全关闭；进入明确宽限期；新增环境和云上传按策略限制。超限升级由服务端原子计数控制，客户端显示预估，支付成功回调确认后才更新权益。降级需先预览超限项，不能自动删除超出部分。

成本模型至少包含：三平台定制内核维护、构建机/测试机、签名账号、对象存储、同步带宽、备份/保留、客服、监控与支付手续费。公式为订阅收入减支付/税费及单位工作空间变动成本，再覆盖工程维护；未拿到试点用量前不编造毛利率。

试点路线：内部 3 人一周 → 3 个团队两周 → 10 个付费意向团队四周 → 分批公开。先配备中文帮助中心、安装说明、代理配置与故障处理、数据备份/导出和支持入口。

产品数据只采集必要事件：完成引导、创建成功/失败、启动、恢复、代理检查、同步结果、邀请接受、套餐浏览和付款结果。默认不上传网页正文、完整浏览历史、Cookie 或代理密码。
