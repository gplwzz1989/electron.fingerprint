# 浏览器指纹隔离改进开发计划

更新时间：2026-10-06  
文档状态：已完成首轮 P0 修复、Locale/Intl 修复、WebRTC 候选采集验证入口和出口位置风险提示；修复后 A/B 四站有效复测已完成，EFF 结果页超时未形成评分（修订版 5）

## 1. 文档目的

本计划依据最新 SaaS 客户端中的五站实测结果，安排浏览器指纹隔离能力的后续改进。目标是先消除跨信号矛盾和网络泄漏，再评估噪声、设备能力和群体分布策略，逐步降低被风控系统判定为异常环境的风险。

本计划不承诺某个网站的固定识别概率。不同网站的样本库、算法、网络条件和历史数据不同，后续结果统一使用风险等级、实测证据和趋势对比表达。

本轮先依据既有五站结果、当前仓库源码、已有构建树相关实现和公开规范完成计划复核，随后实施了环境种子隔离、权限处理器统一、WebGL 像素噪声开关修复以及 Renderer 的 Locale/Intl 初始化修复。Release 已完成最小增量编译并通过应用层、跨进程环境恢复、标签和打包数据目录测试；A/B 五站结果作为修复前基线归档，修复后已完成 CreepJS、BrowserLeaks、Pixelscan 和 AmIUnique 的有效页面复测，EFF 结果页在本次超时内未形成评分，P1/P2 任务仍需按本计划执行。

### 2.3 已确认的有效能力

1. 不同环境使用独立 Session、Cookie、本地存储和配置目录。
2. 语言、时区、线程数和屏幕尺寸能按环境配置生效。
3. 同一环境重复打开时 Canvas 签名保持稳定。
4. 不同环境能产生不同 Canvas 签名。
5. 现有环境记录、配置快照和恢复机制可以作为后续改进的生命周期基础。

### 2.4 已记录的测试问题与待归因项

1. 检测页报告 WebGL 一致性告警；屏蔽值与未屏蔽值不同本身符合 API 设计，不能单凭字符串不同认定缺陷。
2. Canvas/WebGL 指纹在多个公开样本库中高度唯一。
3. Pixelscan 持续报告指纹不一致、检测到伪装和自动化行为。
4. CreepJS 未检测到桌面媒体设备。
5. 环境 A 曾出现 WebRTC 本地 IPv4 地址暴露，且与远端地址不匹配；后续测试因 STUN 域名解析失败显示为 `-`，因此不能视为已彻底修复。
6. Client Hints 的 JavaScript API 可见，但站点显示首次 HTTP 请求缺少相关头。低熵头与高熵头需要分别核实；页面显示不能代替服务器实际收包记录。
7. 时区与网络出口不一致时会触发 Pixelscan 告警。
8. 字体、插件、权限、媒体信息和硬件信息组合仍可能形成少见的整体画像；字体数量本身不是缺陷证据。

### 2.5 复核结论与证据边界

**原计划可以指导隔离和一致性修复，但不足以证明抗指纹能力提高。** 缺少单变量对照、噪声开关的真实语义、跨站关联指标和明确的发布门槛；部分异常归因也需要纠正。本次修订补齐这些环节，完成后的效果仍必须由实际发行包回归证明。

| 原判断 | 复核后的判断 | 对计划的调整 |
| --- | --- | --- |
| `WebKit` 与 `Google Inc. (Intel)` 不同就是 WebGL 矛盾 | 常规 VENDOR/RENDERER 与调试扩展的 UNMASKED 值承担不同职责，可以不同 | 先对照同版本原生行为及检测规则，禁止把四个字符串强行改成相同 |
| JavaScript 可见高熵信息，首次请求不发送就是缺陷 | 高熵头受 Accept-CH、策略和请求范围影响；低熵头在正常 HTTPS 条件下通常默认发送 | 用受控 HTTPS 回显端点验证协商和实际请求链，确认后修复 |
| 媒体设备为空就是异常伪装 | 无设备、权限与系统限制都可能合法地返回空结果 | 保留真实设备语义，不为消除告警虚构摄像头或默认授权 |
| A/B 分数差异能证明噪声改善 | A/B 同时改变语言、时区、硬件线程、屏幕和多种噪声，无法分离因果 | 在同一模板下逐一开关模块，补齐两环境在各站未测的组合 |
| 关闭 Canvas/Audio/Rects 就代表所有噪声关闭 | 当前 WebGL 噪声实现另有触发路径，未遵守上述开关 | 先修 P0-06，再建立真正无噪声基线 |
| 稳定且环境间不同的指纹就是抗追踪 | 稳定的唯一指纹也能成为长期识别标识，跨站相同会支持关联 | 引入按顶级站点分区的受控策略和直接关联实验 |
| 常见模板能保证公开库不唯一 | 模板只能约束显性组合，不能复制真实 GPU、字体度量和渲染输出；公开库也存在抽样偏差 | 常见度作为参考，核心验收改为泄漏、一致性、关联和兼容性 |

五站结果不构成“两环境 × 五站”的完整矩阵：AmIUnique 已记录 A，EFF 已记录 B，不能写成两环境均已在这两站完成测试。EFF 报告采用 `aat=0`；追踪广告与隐形追踪器阻断均为“No”，这属于需要独立验证的请求阻断能力。不同站点的识别信息位数不可相加；历史样本唯一率也不是现实网站识别成功率。

## 3. 风险分级与改进目标

### 3.1 风险分级

| 等级 | 当前问题 | 风险判断 | 处理要求 |
| --- | --- | --- | --- |
| P0 | 测量归因、噪声开关缺口、权限自动放行、WebRTC 泄漏，以及核实后的协议/图形矛盾 | 已确认源码问题优先修；站点告警先复现归因 | 先完成 P0-01，再安排 P0-06/P0-07 与其余有证据的修复 |
| P1 | 跨站稳定标识、噪声 API 语义、设备能力、Pixelscan 自动化归因 | 对提高抗指纹能力直接相关；缺失设备不直接判为缺陷 | 完成按站点分区、模块消融和正常启动回归 |
| P2 | 群体模板、历史趋势、请求阻断和发行前报告 | 模板与阻断需独立衡量，不能替代防关联验证 | 形成版本化交付与发布门槛 |

### 3.2 总体目标

- **一致性优先**：同一环境在配置、JavaScript、请求头、WebGL、网络和权限层表达相互匹配。
- **隔离可证明**：不同环境的 Session、存储、网络和指纹快照互不串用；同一环境在生命周期内保持稳定。
- **异常可解释**：每个指纹点区分“已启用、未启用、不支持、未验证、实测一致、实测不一致”。
- **群体性评估**：不以单个 Canvas 签名不同作为成功标准，增加常见设备模板和跨站历史对比。
- **兼容性优先**：无配置、关闭能力或底层不支持时保留原生行为，不用站点专用硬编码绕过。

### 3.3 当前效果判断

| 评价维度 | 当前判断 | 实测依据 |
| --- | --- | --- |
| 环境隔离 | 良好 | 两个环境 Session、Cookie、存储和配置目录不同；同环境 Canvas 稳定，环境间签名不同 |
| 配置生效 | 良好 | 语言、时区、线程数和屏幕尺寸能随环境配置变化 |
| 跨信号一致性 | 存在告警，根因未全部确认 | Pixelscan 报告 `inconsistent`；WebGL 差异需对照规范与实际规则 |
| 唯一性控制 | 不足 | BrowserLeaks、AmIUnique 和 EFF 均显示 Canvas/WebGL 或整体指纹高度少见 |
| 网络隐私 | 需优先修复 | 环境 A 曾暴露本地 IPv4；STUN 失败导致后续结果无法证明策略可靠 |
| 被识别可能性 | 高 | Pixelscan 报告伪装和自动化行为；EFF 至少 18.46 bits；AmIUnique 标记为历史样本中的唯一指纹 |

“被识别可能性高”表示当前组合容易被公开测试站或风控规则标记为独特、矛盾或自动化环境，不表示任何真实业务站点必然以固定百分比识别。后续版本必须同时观察唯一性、矛盾项、网络泄漏和自动化告警的变化。

### 3.4 抗指纹目标与策略选择

必须分别报告三个结果：环境隔离、浏览器行为一致性、基于指纹的跨站/跨环境关联。Cookie 隔离和 Pixelscan 告警减少可以改善前两项，却不足以证明第三项。

沿用稳定环境快照，新增可选择的“按站点防关联”策略：同环境同顶级站点的敏感读回值稳定，不同顶级站点使用不同派生种子；页面、嵌套 iframe 与可用 Worker 按其实际所属的顶级站点执行，不能由 iframe 自报域名决定。环境恢复保留站点内身份；换站点不会复用同一敏感哈希。旧环境迁移须显式选择并生成新快照，禁止热改已锁定 Session。

本期优先实现持久化的“环境 × 顶级站点”分区，不默认每次启动轮换种子。需要会话级隐私时再提供明确的轮换选项，并单独验收恢复兼容性。该策略仍可能产生公开样本中的唯一哈希，验收重点是能否直接跨站关联以及是否能从多个读回结果恢复同一个真实设备特征。

公开站点分数是辅助指标。不能为了提高分数虚构硬件、把权限设为全部允许、篡改 API 缺失状态，或让唯一性改善掩盖网络泄漏。

## 4. 开发原则与范围边界

### 4.1 分层原则

按照“应用层配置 → Electron 校验与 Session 管理 → 跨进程适配 → Chromium 能力执行”传递数据。

- 应用层负责环境、模板、存储和产品规则。
- Electron 负责配置校验、Session 所有权、生命周期和能力开关。
- 跨进程入口只传递必要字段或只读快照。
- Chromium/Blink/V8 只实现所属能力，不依赖 Electron 业务对象、页面代码或应用存储。

候选入口优先使用现有的 `fingerprint_profile_parser.*`、`fingerprint_context.*`、`fingerprint_config.*`、Session API 和网络适配入口。只有现有公开接口无法实现时，才在对应 Chromium 能力模块增加最小私有修改。

### 4.2 明确不做的事项

- 不针对单个测试站点写专用绕过逻辑或硬编码结果。
- 不把 Coverage、唯一性或某一站点分数直接换算为固定被识别概率。
- 不随机重写全部指纹点，不让同一环境每次启动都变化。
- 不立即修改上游公共头、全局编译参数、架构、优化、LTO 或构建配置。
- 不为本计划新建构建目录，不清理已有缓存，不执行全量 Chromium/Electron 编译。
- 不因一次站点结果异常就删除环境数据、重置 Session 或覆盖原有配置。

## 5. 分阶段开发任务

### 第一阶段：固化测量和修复 P0 一致性问题

#### P0-01 测试采集与环境基线固化

**问题证据**：目前五站结果已采集，但网络出口、浏览器启动方式、远程调试状态和 STUN 可用性会影响结果，部分页面只记录了可见结果，难以进行版本间精确比较。

**所属层**：`fingerprint-browser` 应用层与验证工具，不涉及 Chromium 原生修改。

**实施内容**：

1. 固定每次测试的客户端版本、内核版本、环境 ID、配置快照、Session 目录、代理出口、DNS、启动参数和测试时间。
2. 为五站建立统一记录表，保存页面截图、站点结果、关键字段、异常说明和网络条件。
3. 将“未检测到、检测失败、站点未返回、能力不支持”分开记录，避免把缺失值误判为防护成功。
4. 记录正常用户启动与开发调试启动两种模式，区分远程调试对自动化检测的影响。

5. 补齐 A/B 的五站记录；对照原生浏览器、同运行时无配置、模块全部关闭、现有默认模板和优化模板。普通浏览器仅用于对照，最终验收必须在 SaaS 发行客户端的独立环境中完成。
6. 使用相同网络、模板、种子、窗口与权限条件进行消融：Canvas 像素/文本、WebGL 像素、Audio、Rects、字体、UA/Client Hints、WebRTC 分别改变一个因素。将正常启动与远程调试分开，不以原 A/B 分数差异证明单个开关效果。
7. 每个固定测试向量在同环境执行 10 次读回、3 次页面重新打开、3 次客户端关闭恢复；两环境分别单独运行、同时运行、关闭其中一个后新建环境，覆盖进程复用和静态缓存生命周期。基线使用可控页面，公开站点每个场景记录 3 次有效结果及失败原因。
8. 建立能力可见范围表：WebGL/OffscreenCanvas 和 Client Hints 按实际 Window/Worker 支持范围验证；ClientRects、媒体枚举、RTCPeerConnection 不预设在 Worker 可用。不支持场景标记为“不适用”，禁止为补覆盖率注入伪 API。
9. 在现有 `test/fingerprint-page.html` 和现有验证脚本上补需要的观测；首次请求与高熵协商需受控 HTTPS 收包。把截图/原始 JSON/响应头与版本哈希归档，不另建测试框架。M0 同时提前执行 P1-04 的启动方式归因。

**前置决策**：在正式评分前完成 P0-06 的开关修复或证实发行包不含该问题；否则“全部噪声关闭”只能标记为未确认。原生浏览器对照尽量使用同主版本与硬件；版本不匹配时记录差异，不将结果作为等价证据。

**验收标准**：同一版本重复测试能还原环境和网络条件；每个结论均能追溯到站点、时间、环境和原始证据；缺失值不再被写成通过。

**预计影响**：仅新增记录和验证流程，不触发原生编译。

#### P0-02 WebGL 厂商、渲染器和屏蔽状态一致性

**问题证据**：检测页报告 WebGL 告警；WebKit、WebKit WebGL 与 Google Inc. (Intel)/ANGLE 的差异本身不能证明错误。现有补丁只覆盖未屏蔽字符串，并未改变实际 GPU、扩展或渲染结果。

**所属层**：Electron 图形适配入口和 Chromium/Blink WebGL 能力模块。

**候选修改位置**：优先核查现有指纹配置解析、WebGL 参数覆盖和 Renderer 创建入口；必要时只修改对应 `fp_*.patch` 所属 `.cc`，不把应用对象引入 Blink。

**实施内容**：

1. 列出 WebGL JavaScript、扩展、Canvas、GPU 信息和未屏蔽参数的实际来源。
2. 为每个环境生成一次稳定的图形配置快照，确保厂商、渲染器、平台和 GPU 能力属于同一模板。
3. 明确屏蔽值和未屏蔽值的关系：未配置时保留原生值，配置时保证所有可见入口使用同一策略。
4. 对不支持或无法安全覆盖的字段返回“未验证”，不伪造已生效状态。

5. 对照 WebGL1/WebGL2、OffscreenCanvas、扩展存在性、着色精度、limits、GPU 后端及可用 WebGPU adapter 信息。只改厂商字符串不能伪装另一块 GPU 的实际能力；优先选择与真实后端相容的模板，禁止从 Intel 任意换成 NVIDIA/AMD 后宣称已完成硬件替换。
6. 保留普通参数与调试参数的正常差别。若隐私策略减少高熵设备信息，明确策略和兼容范围，并防止从其他接口直接取得同一真实标识。
7. 将字符串覆盖与像素噪声拆开验证；先执行 P0-06 再判断图形告警来自参数、能力、像素路径还是检测规则。

**验收标准**：固定图形向量无 GL 错误或崩溃；同一策略范围内结果稳定，厂商、后端和能力组合可解释；普通与未屏蔽字符串不要求相等。确认由本系统引入的矛盾必须修复；原生对照也触发的站点启发式告警记录为规则差异，不能用“已归因”替代真实缺陷修复。

**预计影响**：可能重编对应 WebGL 能力实现及最终链接目标；修改前后必须在现有 Release/Testing 输出目录执行 Ninja 预演，确认只重编实际受影响目标。

#### P0-03 WebRTC、ICE 候选和 STUN 泄漏

**问题证据**：环境 A 首轮暴露本地 IPv4 地址，且与远端 IP 不匹配；后续环境 B 因 STUN 域名解析失败显示为空，不能证明策略可靠。

**所属层**：Electron 网络配置、Session 代理策略和 Chromium WebRTC 网络能力。

**候选修改位置**：现有网络偏好、代理和 WebRTC 配置入口；必要时在对应 Chromium 网络模块做局部适配。

**实施内容**：

1. 明确每个环境的代理出口、DNS 解析路径、ICE 策略和允许的候选地址类型。
2. 在代理不可用、STUN 不可达、DNS 失败和直连禁止时分别记录实际行为，禁止静默回退到直连。
3. 在实际支持 RTCPeerConnection 的页面和 iframe 中验证候选、SDP 与 `getStats()`；Worker 无该 API 时记录不适用。
4. 将“无候选地址”与“候选地址被正确代理”分开验收，避免把网络故障当成隔离成功。

5. 优先在新建隐私环境启用现有 `modules.webrtc` 与 `disable_non_proxied_udp` 路径，显示实际生效状态；旧环境提示风险并允许受控迁移。模块关闭本来就不承诺 WebRTC 防泄漏，不能把关闭场景写成已保护。
6. 覆盖 host、srflx、relay、mDNS、IPv4/IPv6、UDP/TCP；至少使用两个确认可达的 STUN 端点和一个可控 TURN 端点。记录连接成功、候选生成和服务端见到的来源地址，单纯无候选不算通过。
7. 复用 `browser-tabs.js` 和 SOCKS5 桥，验证建立代理后断线、认证失效、WebSocket/子资源/重定向等实际连接路径。当前 SOCKS5 桥只支持 CONNECT，不声称它支持 UDP ASSOCIATE；非代理 UDP 策略可能导致实时通信受限，使用实际 TURN/TCP 验证回退能力。

**验收标准**：保护开启且端点可达时，候选、统计及服务端日志不暴露禁止的本地地址或真实直连公网地址；代理故障在启动前和运行中均不回退直连。模块关闭准确显示未保护；端点不可达为测试无效。域名由代理解析的承诺只适用于已核查的路径，不能据此宣称整机无 DNS 泄漏。

**预计影响**：可能涉及网络和 WebRTC 目标的必要增量编译；不得清理缓存或切换构建配置。

**当前进度（2026-10-06）**：已在 `fingerprint-browser/test/fingerprint-page.html` 增加 ICE、SDP 和 `getStats()` 候选采集与分类，并在 `test/unified-tabs.test.js` 对开启 `modules.webrtc` 的环境验证非 mDNS UDP host 和 UDP srflx 候选未出现。无 STUN 配置时，开启保护的环境为 `no-candidate`，统计中仅有 `0.0.0.0`、`::` 的 TCP 占位候选；关闭保护的对照环境生成了 mDNS host。使用 `stun:stun.l.google.com:19302` 和 `stun:stun.cloudflare.com:3478` 的受控探测中，开启保护的环境仍无 UDP 候选，关闭保护的环境出现 mDNS host 和一个 srflx 公网候选，同时记录了 STUN 主机查找错误。该结果已证明现有开关能阻止本次可见的 UDP 公网候选，但代理出口、TURN/中继和服务端来源地址仍待独立验证。

#### P0-04 时区、语言与网络出口一致性

**问题证据**：环境 A 配置 Asia/Shanghai 时被 Pixelscan 报告时区与网络位置不一致；环境 B 改为 America/Los_Angeles 后时区告警消失。

**所属层**：应用模板校验、Session 配置、网络出口选择和 Renderer 暴露值。

**实施内容**：

1. 新建或更新环境时检查语言、时区、地区、代理出口地和屏幕模板的组合。
2. 对无法确认出口地的代理标记为“网络位置未验证”，不自动声称一致。
3. 在配置页显示组合校验结果，并在保存前提示高风险组合。
4. 复测 JavaScript 时区、请求语言、Accept-Language、IP 地理位置和站点显示结果。

5. 检查 Intl、Date、历史日期和夏令时转换，而不仅是当前时区名称。语言/地区与 IP 不同可能是合法漫游或个人偏好，只提示风险；不得强制把所有字段改为 IP 国家。匹配模板使用实测出口而非手填代理名称，地理库不确定时保留“未验证”。

**验收标准**：受控匹配组和故意错配组的实际值正确；Intl/Date 和夏令时无系统引入的矛盾；错配可提示并允许合理用途；正常启动的匹配组若仍有时区告警须保存证据继续归因，不保证第三方地理库一定判定通过。

**预计影响**：以应用层和现有校验入口为主，不触发原生编译；若需请求头适配，按 P0-05 单独预演。

**当前进度（2026-10-06）**：创建向导已增加“网络出口位置尚未验证”提示，明确代理地址不能证明地理位置，语言、地区和时区需要在实际出口下联合检查。当前仍不自动查询或强制改写地区，受控出口匹配组和故意错配组的公网地理验证待补齐。

#### P0-05 Client Hints 请求头与 JavaScript API 一致性

**问题证据**：BrowserLeaks 页面显示 JavaScript 值可见、首请求相关头缺失；缺少受控收包，尚不能直接确认协议缺陷。源码另发现品牌版本覆盖与 GREASE 处理风险。

**所属层**：Electron User-Agent/网络请求适配与 Chromium Client Hints 能力。

**实施内容**：

1. 梳理 User-Agent、低熵和高熵 Client Hints 的生成时机、权限策略、首个导航请求和后续请求差异。
2. 明确哪些值由环境配置提供，哪些值必须由 Chromium 原生计算。
3. 对照请求头、JavaScript API、Worker 和 iframe 的可见值，避免只修复页面脚本层。
4. 记录服务端未请求 Client Hints、浏览器未发送和配置不一致三类情况。

5. 在可信 HTTPS 下分别验证低熵头 `Sec-CH-UA`、`Sec-CH-UA-Mobile`、`Sec-CH-UA-Platform`，以及经 `Accept-CH` 协商的 Full-Version-List、Arch、Bitness、Platform-Version。检查权限策略、重定向、缓存与代理转发；不向未协商的站点强塞高熵头。
6. 追踪 `ApplyClientHintsOverride`、WebContents UA 覆盖、导航恢复和首个加载路径；统一使用现有元数据覆盖能力，保留 Chromium 生成的 GREASE 品牌及版本逻辑，不把所有品牌改成相同版本。UA 缩减版本与高熵完整版本可以按规范不同，不能全部硬拼为 `138.0.0.0`。
7. 限制模板声明为真实运行时支持的平台/版本。`architecture=x86` 配合 `bitness=64` 可以合法表示 x64；Win32 并不表示 32 位系统。不能为了新版本外观修改版本常量或把 Chromium 138 声称为未知最新版本。

**验收标准**：受控服务端收到的低熵头符合 HTTPS/策略条件；高熵头符合协商范围，脚本与已发送字段语义一致；真实品牌版本正确且 GREASE 保留原生规则；首次导航、恢复导航和支持的 Worker 路径无配置串用。

**预计影响**：优先使用现有 User-Agent/网络接口；若需要 Chromium 修改，只改 Client Hints 所属实现并执行增量预演。

#### P0-06 修复图形噪声开关语义

**问题证据**：WebGL 噪声在 `modules.webgl=true` 且种子非空时启用，即使 Canvas 噪声关闭。默认模板仍有 WebGL 模块和种子，因此原 A 不能直接视为真实无噪声组。

**所属层与入口**：Electron 配置契约、现有解析与序列化、应用配置说明；Chromium WebGL `GetFingerprintWebGLOverride` / `ReadPixelsHelper` 和对应补丁。

**实施内容**：本期优先复用现有开关，明确“图形像素噪声”的启用条件为总开关开启、WebGL 模块开启、`modules.canvas && noise.canvas` 开启且种子有效；仅覆盖厂商字符串时不应自动加噪。该契约是待实施的最小方案，须核对所有已有调用方并更新界面说明；若必须提供独立 WebGL 噪声开关，再提交最小 Schema/协议变更及旧环境兼容方案。保留非法参数、缓冲区大小、格式及 pack 对齐的既有检查。

**验收标准**：无配置、总关闭、WebGL 关闭、图形噪声关闭四种场景都不执行本项目 WebGL 噪声；开启才生效。相同固定像素向量读回 10 次稳定；合法调用不崩溃，非法输入保留原生错误语义。必须覆盖 WebGL1/2、不同读回格式、偏移与缓冲区边界，未保护路径列为能力限制。

**影响与依赖**：先验证发行包含此行为；确认后仅修改所属实现、补丁和必要应用文案，在原输出目录预演。此任务先于正式无噪声基线及 P1-02。

**旧环境兼容**：修正隐式噪声也可能改变旧环境指纹。先记录算法/策略版本和旧行为，新增环境使用修正契约；旧记录缺少版本时按已核查的历史行为解释并提示迁移，不能按新版缺省值悄悄改写。旧策略不得标为受保护，用户选定迁移时保存旧快照及回滚路径。若无法合法兼容旧策略，不执行会静默改变恢复结果的发布，先明确受影响环境与迁移方式。

#### P0-07 权限请求与检查统一

**问题证据**：当前 `openPage` 对除外部协议之外的权限请求全部允许；缺少配套检查处理器。该源码问题能暴露真实媒体/定位等信号，且与原计划“默认不向所有来源开放”不符。

**所属层与入口**：应用层 `browser-tabs.js` 和环境授权记录；复用 Electron `setPermissionRequestHandler`、`setPermissionCheckHandler`，涉及硬件设备时核对相应设备授权入口。

**实施内容**：按环境、请求来源、顶级来源和权限类型保存用户决定。敏感权限需用户授权，未授权不自动放行；检查和请求处理器读取同一决策，覆盖 iframe、权限撤销和重启恢复。不能把普通检查伪装为全部 granted，也不能为补“媒体设备为空”而自动允许麦克风。

**验收标准**：环境 A 的授权不被 B 继承；同源授权、拒绝、跨源嵌套请求和撤销结果与支持的 Permissions API/实际调用一致；无设备时保留真实结果。复用现有运行时，无需原生编译；P1-01 在此基础上验证设备行为。

### 第二阶段：处理 P1 能力缺失和噪声策略

#### P1-01 媒体设备能力与权限策略

**问题证据**：检测页未发现媒体设备，需区分真实设备状态与检测启发式；不能据此断言必须提供虚构设备。先完成 P0-07 权限策略修复。

**所属层**：Electron 权限管理、媒体设备枚举和 Session 生命周期。

**实施内容**：

1. 区分“真实无设备”“设备被策略隐藏”“权限未授予”“站点未请求”四种状态。
2. 为环境建立摄像头、麦克风权限策略，默认不向所有来源开放权限。
3. 验证 `enumerateDevices`、权限查询和实际媒体请求的结果是否互相匹配。
4. 对没有真实设备的环境采用一致的能力声明，不返回与平台模板明显矛盾的设备信息。

5. 在真实有设备和无设备的条件下分别测试；检查授权前后 deviceId、groupId、label 和实际媒体获取结果。验证环境间标识隔离、同环境生命周期及权限撤销；实际浏览器已有的标识保护应优先复用，不向页面暴露物理设备唯一标识。

**验收标准**：媒体设备和权限结果可解释、稳定，并与配置及操作系统能力一致；授权只作用于当前环境和来源；关闭能力时不影响普通页面加载。

#### P1-02 Canvas、Audio 和元素尺寸噪声策略

**问题证据**：Canvas 高度少见；B 在 EFF 和 Pixelscan 仍出现唯一或异常结果，AmIUnique 已记录的是 A，不能外推到 B。源码中的 Audio 采样率改动、Rects 固定偏移和文本度量缩放可能留下可检测特征，需单模块实验确认。

**所属层**：Chromium Canvas/Audio/布局能力模块，配置种子由 Electron Session 快照提供。

**实施内容**：

1. 先验证噪声是否跨 API、跨 Worker、跨 iframe 一致，再调整噪声强度。
2. 同一环境使用稳定种子，避免页面刷新或标签切换时结果漂移。
3. 评估噪声对文本、图像、音频、元素尺寸和无障碍信息的副作用。
4. 增加“关闭、稳定噪声、未支持”三种明确状态，不把每次随机化作为默认策略。
5. 以群体分布和跨信号一致性为目标，不以单次改变 Canvas 签名作为通过条件。

6. 优先取消经复现确认会改变 API 语义的实现：OfflineAudio 保持请求采样率、缓冲区长度、时长关系；必要的保护在适合的输出边界执行。文本度量与实际字形/CSS 度量的关系、Rects 坐标与滚动/缩放的关系均须遵守 API 契约。未证实有效的文本和几何噪声默认关闭，不同时扩大扰动面。
7. Canvas 验证 getImageData、toDataURL、toBlob、OffscreenCanvas 导出/转移、复制和局部读回；WebGL 验证 readPixels 格式、typed array/PBO 等实际支持路径。比较语义等价读回的解码结果，不能只比较哈希；要求边界规则一致而非所有不同 API 的哈希都相等。
8. 增加已知输入、空白/纯色、局部裁剪、多次读回与复制回写实验，检测重复施噪、未保护读回旁路、均值恢复和种子特征反推。保持透明度、色彩与缓冲区语义；不能通过只修改一个 API 留下原图读回旁路。
9. 每个能力记录保护入口、未覆盖入口和兼容性限制。方案若只能让哈希改变，却能通过另一入口还原真实特征，状态标记为“保护不足”，不发布为抗指纹完成。

**验收标准**：固定向量在相同环境/站点下 10 次读回保持约定稳定；语义等价 API 无未经解释的矛盾；采样率、时长、坐标及文本关系正确；已定义的读回旁路和简单恢复探测不能直接取得同一原始标识。公开库继续唯一不自动判失败，但必须用 P1-05 的关联实验证明改进；不能只用“分数不恶化”验收。

**入口与影响**：复用现有 Canvas、OfflineAudio、Rects 和 TextMetrics 补丁及所属实现。优先以现有开关关闭不合格策略，再做必要的局部修复；涉及 Document/TextMetrics 头文件时先追踪已有调用与聚合目标，不扩大公共接口。

#### P1-03 字体、插件、权限、屏幕和硬件组合

**问题证据**：BrowserLeaks 检测到 114 个字体、79 个唯一度量；AmIUnique 能读取字体、插件、权限、设备内存、硬件线程和屏幕等字段。单项看似合理的值组合后仍被标记为唯一。

**所属层**：应用模板校验、Renderer 能力暴露和 Session 权限。

**实施内容**：

1. 建立平台模板约束，检查语言、字体、屏幕、线程、设备内存、GPU、插件和权限的组合关系。
2. 不伪造系统不存在的插件或设备；对不支持的能力返回一致的缺失状态。
3. 统一窗口、屏幕、设备像素比、元素尺寸和浏览器缩放之间的关系。
4. 为模板增加“常见度”和“兼容性”字段，保存选择依据，便于历史比较。

5. 字体列表、CSS 字体匹配、Canvas 文本、字体加载和系统字体回退必须属于同一真实可用集合；本地特殊字体是否泄漏需实际验证。屏幕/DPR/视口/缩放按规范检查，而非固定要求它们数值相等；设备内存保留浏览器合法量化值。
6. 盘点可用 WebGPU、插件/MIME 类型、PDF 能力、触摸与媒体查询、权限、硬件线程和屏幕方向等旁路。只对实际暴露且能够关联宿主的信号安排修复；不要为完整清单新建全局覆盖系统。

**验收标准**：配置值与页面实测值一致；同一模板在多站的组合不出现明显矛盾；不支持项不会因页面差异而随机变化。

#### P1-04 Pixelscan 自动化判定归因与正常启动复测

**问题证据**：两个环境都出现 `Automated behavior detected`；测试期间使用了远程调试和自动化操作，可能放大该信号。

**所属层**：验证流程与客户端启动方式，必要时再进入内核能力分析。

**实施内容**：

1. 使用正常用户启动、开发调试启动和自动化启动三种方式分别测试。
2. 记录远程调试端口、启动参数、窗口状态、操作节奏和页面加载顺序。
3. 仅在正常启动仍稳定触发时，继续定位浏览器暴露的自动化特征。
4. 将站点自身的自动化判断与真实指纹不一致分开统计。

5. M0 先执行启动对照。已有 webdriver 与 runtimeInspector 补丁不等于“不可检测”；检查其实际启用状态、错误/堆栈、属性描述、frame/worker 差异与开发调试副作用。确认会损害正常行为的补丁优先通过配置回退，禁止靠伪造人类点击节奏掩盖浏览器缺陷。

**验收标准**：能判断自动化告警来自测试方法还是客户端行为；正常启动条件下的结果纳入正式发布门槛；不为单一站点添加专用绕过。

#### P1-05 按顶级站点分区的防关联策略（抗指纹核心任务）

**问题证据**：Canvas 自定义种子没有站点域；WebGL 使用固定标识派生。当前跨站稳定环境标识与长期隐私目标相冲突，仅更换模板不能解决。

**所属层与入口**：应用选择和环境快照由 Electron 管理；Chromium 能力模块复用合法的执行上下文、顶级站点和 Canvas 现有域隔离入口。不得把 Electron 头文件引入 Blink。

**实施内容**：

1. 为新隐私环境建立不可向网页暴露的随机环境密钥；必须在环境创建时生成，不能只复制配置草稿的种子，恢复时保留。复用所在层现有密码学能力（如 HMAC-SHA-256），按“策略版本、环境密钥、顶级站点、能力标识”生成种子；核查噪声消费方是否又压缩成可枚举的短哈希，不能仅凭输入是随机 UUID 就宣称保护不可逆。具体字段变更在 M1 确认 Schema/传输兼容后实施，不新增通用插件框架。
2. 顶级站点采用浏览器现有的 schemeful site/公共后缀解析，不能用字符串末两段截取；opaque origin、about:blank、sandbox、iframe 继承关系用实际安全上下文处理。第三方域在不同顶级站点下得到不同种子，同一顶级站点内的可用 frame/Worker 使用相同分区规则。
3. 修正目前从进程命令行读取并全局静态缓存种子的使用方式：缓存只保存符合生命周期的环境数据，站点相关派生在实际上下文中完成。核查共享 Worker、ServiceWorker、Renderer 重启和进程复用；不支持共享上下文的保护路径必须明确报限制，不能擅自取首个访问站点。
4. 先落实最小保护面：Canvas/WebGL 像素读回，并对 Audio 完成 P1-02 后按同一分区规则保护。文本/几何噪声只有通过语义和兼容性验证才启用。不要把一个相同哈希作为跨能力公开输出；实际关联仍须检查剩余字体/GPU 等不变信号。
5. 构建两个受控顶级站点及共同第三方 frame，执行相同固定向量。分别测同站刷新/恢复、换顶级站点、换环境和通过其他 API 读取原值；登录、Cookie 和授权记录仍由原环境 Session 管理。
6. 在预定义匹配规则下同时尝试原始哈希、相似性、字体/GPU 等组合关联；只改变精确哈希不足以通过。可获得时加入至少两台不同 GPU/字体配置的真实宿主作对照，记录“同宿主不同环境”和“不同宿主”是否仍可区分；缺少第二宿主时标明硬件关联未验证，不声称已隐藏真实宿主。

**验收标准**：同环境同顶级站点在 10 次读回、3 次重开、3 次客户端恢复中保持稳定；相同高熵向量在两顶级站点、同第三方嵌入和两环境之间无完全相同的受保护哈希。对预定义恢复/旁路探测，不能直接提取同一宿主原始标识。该小样本结果仅证明覆盖场景，不宣称真实世界无法关联。

**交付物**：策略契约、分区继承表、种子迁移/回滚说明、关联实验原始结果、未保护信号清单。若仍有稳定旁路，报告“部分保护”并继续限制发布宣传。

### 第三阶段：形成 P2 群体模板和发布回归

#### P2-01 常见系统模板与环境群体分布

**问题证据**：A、B 的 Canvas 签名均接近唯一，说明“每个环境都不同”没有转化为“多个环境融入常见群体”。

**所属层**：应用模板库、配置校验和数据分析，不优先修改原生能力。

**实施内容**：

1. 建立有限数量的常见平台、浏览器版本、语言、时区、屏幕和 GPU 组合。
2. 为模板设置稳定种子范围和兼容性规则，禁止无约束随机组合。
3. 统计多个环境的 Canvas、Audio、WebGL、字体和屏幕联合分布，而不是只看单个哈希。
4. 为模板提供版本化和回滚，旧环境继续使用旧快照。

5. 模板以实测真实平台/后端为来源，先交付少量验证过的组合。禁止仅通过字符串标签宣称跨操作系统或跨 GPU 模拟。模板常见度保存样本来源与时间，缺少代表性样本时标为“未验证”；共享噪声种子不作为制造匿名群体的办法。

**验收标准**：模板无已确认组合矛盾且符合运行时能力；显性字段常见度有来源。联合分布、公开库唯一性和 P1-05 关联结果分别报告；模板无法保证公开库不唯一，不能把此承诺作为硬性验收。

#### P2-02 跨站回归矩阵与发行前报告

**问题证据**：五站使用不同指标，单站分数无法代表整体效果；站点样本库会变化，需要保存历史趋势。

**实施内容**：

1. 固化五站测试入口、测试顺序和证据采集格式。
2. 每个版本至少覆盖：默认配置、关闭配置、无代理、有效代理、语言/时区匹配和故意错配。
3. 对每个环境检查同环境稳定性、环境间隔离、请求头一致性、WebRTC、WebGL 和媒体能力。
4. 生成发行前报告，列出已验证、未验证、已知限制和与上个版本的变化。

**验收标准**：报告可重现、可比较；P0 项无未解释的高风险回归；任何“通过”都附有原始站点证据或明确的本地验证依据。

#### P2-03 追踪请求阻断与兼容性

**问题证据**：EFF 的追踪广告、隐形追踪器阻断均为“No”；此前计划未安排相应能力。阻断已知追踪请求可减少采集机会，但不是降低指纹唯一性本身。

**所属层与入口**：应用层按 Session 使用现有 `webRequest` 接口，与已有回调统一协调；先核查是否已有拦截处理器，禁止覆盖其他订阅。名单来源、更新和许可须可追溯，具备站点例外与版本回滚。

**实施与验收**：先以固定可审计规则集验证已知追踪请求被阻断，普通内容和登录请求不被误杀，再扩大覆盖。五站复测记录是否因拦截导致检测脚本失效；站点无法完成测试只能标记无效。EFF 阻断项与指纹项分栏汇报，本任务不阻塞 P1-05 核心防关联验收。

### 6.1 抗指纹改进的量化记录

每个版本按相同向量和网络条件记录，避免把站点数据库变化作为本次算法效果。

| 指标 | 计算与记录方式 | 本期验收要求 |
| --- | --- | --- |
| 同站稳定率 | 同一环境/站点/向量重复读回，统计与首次结果相同的比例 | 确定性保护向量 10/10；恢复 3/3；有动态来源的字段单独定义，不混入统计 |
| 受保护向量直接跨站相同率 | 相同向量在不同顶级站点的成对哈希比较，包含共同第三方上下文 | 定义范围内 0 次完全相同；记录总比较次数；失败说明保护未生效，零相同也不证明不能推断关联 |
| 同模板跨环境相同率 | 从同一配置创建两个新隐私环境，比较受保护向量与环境密钥归属 | 密钥不同、受保护高熵向量无相同；原有显性字段可以相同 |
| 原始特征旁路/恢复 | 对预先定义的未加噪入口、复制读回、简单恢复及组合匹配逐项记录 | 不能直接取得共同原始标识；相似性/字体/GPU 仍能关联时列为剩余风险，不用零哈希相同掩盖 |
| 矛盾与泄漏 | 本地契约检查的矛盾数、服务端/ICE 中禁止地址与直连事件数 | 已确认系统缺陷 0 个未解决；保护开启场景禁止事件 0 次；不可达测试不进入通过分母 |
| 五站趋势 | 同场景 3 次有效结果，记录原始分数/状态、范围、样本规模与时间 | 已证实由系统引入的告警减少；仍有告警逐项归因，不能以站点改规则宣称修复 |
| 兼容回归 | 预定义关键用户流程，与基线逐项对照 | 本次改动新增关键失败 0 项；站点本身故障记录为无效 |

对公开数据库继续显示唯一的环境，同时报告受保护向量能否跨站直接匹配、剩余设备特征是否仍可关联；两个结果不能相互替代。正式报告不输出单一“抗指纹分数”或未经统计校准的识别概率。

### 6.2 发布门槛与问题止损

1. **基础修复完成**：P0-06/P0-07 和已复现的泄漏/协议/图形缺陷修复；关掉噪声能得到真实无噪声对照；算法升级的显式迁移/回滚、环境隔离、旧环境恢复和关键流程通过。满足此门槛只允许声称基础修复完成。
2. **按站点抗指纹改进完成**：P1-02/P1-05 通过上述稳定、分区、旁路、恢复和兼容检查；发行包自身复测成功，且已确认系统缺陷不存在。保护范围和剩余可关联信号必须写入报告，允许使用“在已测范围内减少跨站关联”表述。
3. **五站交付完成**：A/B × 五站可复核的正常启动结果齐全；测试工具、页面版本和网络条件清楚。持续不一致/伪装告警若来自未修系统行为，继续标为未完成；若原生对照同样出现或规则不可知，则记录限制，不能承诺全部转绿。
4. 实验中发现新策略增加旁路、API 矛盾或关键流程失败，先将该策略从新环境默认项中撤回，保留旧快照和数据；修复后再放行。只改变哈希或分数上升不能抵消上述失败。

### 6.3 测试问题与解决能力对应表

| 原测试问题 | 对应任务 | 可解决范围与剩余限制 |

## 7. 依赖与风险

1. **网络出口**：代理地理位置、DNS、STUN 可用性会直接影响时区、WebRTC 和请求头结论。
2. **浏览器能力**：部分字段由 Chromium 原生决定，应用层只能报告“不支持”或“未验证”，不能保证覆盖。
3. **站点变化**：五个站点的样本库、规则和页面结构会变化，不能把一次分数视为永久基线。
4. **测试方式**：远程调试、脚本自动化和非正常启动可能触发自动化告警，必须与正常启动结果分开。
5. **性能与缓存**：涉及 Chromium 的修改必须复用 `J:\awork\electron-fp-build\src` 及现有 Release/Testing 输出目录；任何大范围重编、构建图异常或缓存不兼容都必须先停止并定位。
6. **数据兼容**：新增配置字段必须同步检查 Schema、解析、序列化、IPC、Session 快照和所有消费方，缺省值必须保持原有行为。
7. **策略取舍**：同站持久稳定帮助环境恢复，却保留同站长期识别能力；跨站分区只能保护已覆盖特征。登录账号、共享出口和其他真实设备信号仍可能关联环境，报告不将它们归为已解决。
8. **内核时效**：Chromium 138 的版本与实际能力也可能被检测。先做真实版本一致性和升级成本评估；如果升级破坏现有缓存兼容性，按仓库约束停止实施并提交替代方案，不能篡改 UA 宣称新内核。
