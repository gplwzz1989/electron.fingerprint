## 1. 最新状态与本期目标

**用户已于本次沟通确认：Pixelscan 检测已经通过，噪音问题已经解决。** 这两项按已完成处理，不再安排噪音修复、算法重写或为确认同一结果而重复检测。后续涉及相关链路变更时，保留已有行为和必要的针对性回归。

本期目标是交付一个可可靠使用、可解释验证范围的小版本：自动化接口受控，所有配置入口遵循同一规则，代理出口探测使用实际环境网络，环境身份和后台上下文保持一致，发布结果能够对应到实际程序。

用户最新执行顺序：**优先第 5 步及 TLS → WebGPU、Worker/iframe 一致性 → 其余应用层任务。** TLS 已明确要求实现，以当前 Chrome 138 为首个目标，锁定 UA 与内核生命周期；同时采集真实 ClientHello、JA3/JA4 对照。用户要求先提交 Git、继续编码，暂不编译。

## 4. 第一批：应用层安全与入口闭环

全部复用现有 Electron 运行时，不触发原生编译。建议拆成四个可独立验收的小提交。

### 4.1 A1：自动化服务访问控制

落点：`automation-server.js`、`main.js`、现有客户端设置入口、`test/automation-server.test.js`。

- 增加显式启用设置，首次默认关闭；使用本机持久化随机凭据，支持更新凭据，响应和日志不泄露凭据。
- 默认仅回环监听，校验 Host 和允许来源；无 Origin 的合法本地脚本凭有效凭据使用。CORS 限制不能代替鉴权。
- 鉴权覆盖环境、标签、脚本执行、媒体诊断和下载等控制入口；公开健康检查如保留，只返回最小状态。
- 默认响应移除代理密码等敏感字段；调试接口默认不开放，确需保留时使用明确的诊断开关并遵循相同访问边界。
- 将本次触及的原始错误和英文用户提示转换为清晰中文；不借此改写无关模块。

验收：缺失或错误凭据不能读取环境、执行脚本或修改数据；合法脚本可完成既有操作；不可信来源、Host 被拒绝；凭据更新后旧值失效；返回值和日志不泄露代理密码。升级说明需告知现有自动化调用方配置凭据。

### 4.2 A2 / A3 / A4：统一保存规则和环境实例契约

落点：`automation-server.js`、`main.js`，以及确有必要的现有配置、环境仓库接口；扩展现有测试，不另建管理器。

- 主进程提供真实运行时和宿主信息，自动化创建及后续修改复用 `assertFingerprintSave`，禁止请求自行声明宿主能力。
- 在分组创建、文件保存和环境目录创建前校验；失败不得留下半成品。
- 区分模板选择、创建实例和更新实例。重复使用同一模板必须创建独立实例；显式更新沿用现有修订冲突检查。
- 创建、列表、详情、启动、停止、删除使用稳定的实例 ID；保存成功与启动失败分别表达，支持按实例 ID 查询和恢复。
- 用真实仓库加临时目录验证生命周期，避免 mock 把配置 ID 与环境 ID 视为同一含义。

验收：同一合法/非法配置经界面和自动化得到一致结论；连续创建两个实例不会覆盖；种子不同、各自重启稳定；拒绝写入及启动失败后的数据状态可核验；旧环境不会因本次入口修复被静默迁移或重置。

### 4.3 A6：代理出口探测及配置预览

落点：`geo-ip.js`、`main.js`、`preload.js`、`renderer/saas-app.js`；复用 `browser-tabs.js` 中的代理配置能力。

- 已有环境使用其实际 Session 发起探测；尚未保存的代理草稿使用临时隔离 Session，应用当前代理后探测并释放资源，不修改默认 Session。
- 采用 HTTPS 探测源；代理失败时明确失败，不回退本机直连伪装为成功，也不将代理凭据发送给地理信息服务。
- 返回实际出口、时间、使用的网络方式及结果来源；国家信息只作为建议，语言与时区不视为必须按 IP 推断。
- 展示调整前后差异，由用户明确应用。若用户选择一起调整语言，保持 `language`、`languages`、`acceptLanguage` 一致，并复用保存前检查。
- 保持已保存种子和环境身份；探测超时、失败、取消时不改草稿。

验收：两个不同测试代理与直连得到可区分的受控出口结果；认证失败、断线和取消均不直连、不写入；应用建议后组合校验通过；用户手动配置可保留。单元测试与受控代理集成测试分别记录，不能用国家映射测试代替网络路径验证。

### 4.4 A5：建立明确的发布必测清单

落点：现有 `scripts/test-fingerprint.js`、`test/fingerprint-isolation.test.js`、`test/fingerprint-network.js` 及 `.github/workflows/fp-validate.yml`。

- 保留普通诊断入口，增加严格验收入口；每项结果区分通过、失败、未测试、不适用，并记录原因。
- 本版本必测清单对应声明能力：A1、A2/A3、A6、配置生效、关键隔离与网络策略。必测失败、未测试或证据缺失不能返回发布合格。
- 扩展已有基线文件，记录提交、实际运行时与发行物哈希、相关原生差异摘要及测试条件；不记录真实用户种子、登录数据和凭据。
- 用户已确认的 Pixelscan 与噪音成果登记为已完成，关联已有记录时复用原记录，不为本计划重复启动检测。
- 轻量检查逐步加入应用测试、Schema 语义和补丁清单一致性；当前 `verify-patches.py` 仅检查基础文件存在，不能称作补丁适用性验证。

验收：人为构造必测失败、缺结果和不适用时状态正确；普通采集完成不再被误解为保护合格。未声明的探索项单列，不让无限扩大测试范围阻塞本期交付。

## 5. 第二批：原生遗留链路逐项收敛

按用户调整优先处理 N1、N2 和 TLS。Unicode 传输、WebGPU 限制和 Worker 语言列表已有最小实现；新增运行时验收待用户允许编译后执行。保留已通过的噪音行为。

### 5.1 N1：中文及 Unicode 配置传输

- 生产方：`electron_browser_client.cc`；消费方：相关 `fp_*.patch` 所指向的 Blink/V8 `.cc`。先完整枚举读取点与当前构建副本的差异。
- 优先统一现有 UTF-8 读取与序列化契约，不改通用命令行函数，不新增跨进程协议，不新建共享配置源。
- 验收输入包括中文 ID/种子、混合 Unicode、转义字符及非法值；检查页面和受支持线程的生效、会话隔离、重复启动稳定性。
- 开启、关闭、无配置按既有契约回退；仅回归受该传输改动影响的已完成能力，保持现有噪音算法和用户已通过的行为。
- 预期构建范围是实际消费 `.cc` 的必要重编与最终链接；数量以预演为准，不能承诺跨模块修改只需一两步。

### 5.2 N2：WebGPU 策略与实际范围

- 在具备 WebGPU 能力的设备和安全上下文中，用当前运行时核验 `requestAdapter` / `requestDevice`；不只判断 `navigator.gpu` 是否存在。
- 优先复用现有 Electron 和 Chromium 控制入口。先确定产品需要会话级策略还是应用级策略，再定位必要的私有 `.cc`，不把全局开关描述为会话隔离。
- 验收保护开关、无配置对照、页面和受支持线程、两个环境同时运行，以及 WebGL 和硬件加速兼容性；设备不支持记为不适用。
- 如现有策略已经满足明确的产品范围，只补准确状态和回归记录，不新增 GPU 身份模拟。
