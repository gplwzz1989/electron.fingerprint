# 栖界产品定义与交互规范

更新日期：2026-10-28。本版按用户确认的模块边界与竞品评审结论优化，替代上一版产品定义。

## 一、产品定位与导航

面向个人与团队的指纹资源、独立浏览环境和平台账号管理系统。

核心对象按“指纹 → 浏览器环境 → 平台账号”组织。代理是独立资源；团队权限和订阅权益由服务端统一控制。

| 导航 | 职责 | 明确边界 |
| --- | --- | --- |
| 工作台 | 进入常用任务，查看真实的最近环境与待处理事项 | 轻量总览，不占用主要业务操作空间 |
| 指纹管理 | 创建、版本化、保存和复用纯指纹配置 | 不包含代理、启动网址、运营字段、账号凭据或环境会话 |
| 浏览器环境 | 引用指纹，配置名称、启动网址和代理，管理独立会话 | 不重复填写整套指纹参数 |
| 代理管理 | 添加、检测和维护可供环境选择的代理 | 可用性、连通性和出口时区必须实际检测 |
| 账号管理 | 添加并授权系统已接入的平台账号，校验与更新授权 | 不允许用户自定义平台、登录地址、识别字段或粘贴授权凭据 |
| 团队成员 | 查看成员，管理角色、操作权限和资源范围 | 服务端执行权限校验，不信任客户端声明 |
| 订阅与用量 | 套餐、权益、实际用量、订单、续费和支付 | 微信支付、支付宝为首期渠道；国际渠道保留扩展接口 |
| 设置 | 个人、客户端、本机数据、更新和诊断 | 不混入指纹、代理和平台账号配置 |

AI 创作模块取消。操作记录模块删除。正式导航和本版原型不保留相关页面、入口、数据、弹窗或自动发帖面板。订单、授权与故障排查必需的内部事件仍由各自服务维护，不形成新的操作记录模块。

## 二、指纹管理

### 2.1 数据范围

指纹的可编辑数据只包含：浏览器与用户代理、客户端提示、系统平台、语言列表、时区、线程数、设备内存、屏幕与缩放、图形厂商和渲染器、稳定噪声种子、画布/音频/字体/实时通信等能力开关。

名称、唯一编号、版本、创建者、更新时间和引用关系属于系统管理元数据。指纹名称不承担环境名称或账号身份的职责。

### 2.2 保存与跨设备使用

1. 服务端保存团队指纹库，客户端按权限读取；创建成功以服务端提交结果为准。
2. 每次修改保存为新版本。已有环境锁定原版本和指纹快照；不得因编辑共享指纹而自动改变已运行或已创建的环境。
3. 同一指纹可以被多个环境引用，但各环境的 Cookie、缓存和浏览数据独立。
4. 跨设备复用的是指纹配置。使用前检查目标设备的平台、内核版本、协议版本及所需能力，不能把文件同步成功等同于指纹已生效。
5. 兼容检查失败时阻止使用，提供选择兼容指纹或另建指纹的入口，不静默降级或改写原配置。
6. 指纹不携带代理、账号凭据或环境会话；环境登录数据迁移需要独立的机制和授权。

### 2.3 页面与操作

指纹列表 → 创建指纹（基础参数 / 图形与保护）→ 校验 → 服务端保存 → 返回列表。详情显示纯指纹参数、版本和引用关系；删除被引用指纹时必须说明影响，并保留已有环境所需快照。

## 三、浏览器环境

### 3.1 缩短创建流程

新建环境采用单页表单：

- 环境名称；
- 启动网址；
- 从指纹列表选择已有指纹及版本；
- 直连或选择已有代理；
- 创建前检查兼容性、代理连通性及指纹/代理时区一致性。

不再要求用户重复完成原来的三步指纹向导。没有合适指纹时，点击“新建指纹”进入指纹流程；保存成功后回填新指纹，保留环境名称、启动网址和代理选择。取消新建时也保留环境草稿。

### 3.2 引用与生命周期

环境保存指纹编号、版本、快照和完整性标识，以及代理引用、名称、启动网址、数据目录与会话状态。运行中需要重启才能生效的字段不可热修改。重新打开沿用相同环境目录和已锁定快照。

跨设备使用同一指纹不等于跨设备自动恢复相同平台登录状态。不同环境即使选择相同指纹，也不能因此共享登录会话。

## 四、代理管理与时区提示

### 4.1 添加代理

代理信息包括名称、协议、服务器地址、端口及可选认证信息。支持的协议由系统能力定义。

检测必须覆盖协议连接、认证、实际请求可达性、出口地址、出口地区和可识别的 IANA 时区。检测结果包含状态、时间和清晰的中文失败原因。未检测或失败的代理不能被标记为可用；不以定时器、随机结果或固定文案替代检测。

凭据在服务端加密保存，接口默认返回掩码或凭据引用；不把密码写回列表或诊断信息。代理修改后旧检测失效，必须重新检测。

### 4.2 环境选择代理

选择代理后重新检查连接和出口时区，对比已选指纹中的时区：

| 检测结果 | 交互 |
| --- | --- |
| 连接失败 | 阻止创建或启动，保留配置，提供重新检查入口；不回退为直连 |
| 时区一致 | 显示实际检查结果与检查时间 |
| 时区不同 | 提示具体差异，允许重新选择指纹、创建独立的新指纹，或明确确认后保留差异 |
| 时区无法识别 | 显示“无法确定出口时区”，不得伪装成一致；提示重检和明确确认 |

不能为解决一次代理时区差异，直接修改整个团队正在复用的指纹。选择“创建新指纹”时保留原指纹，使用检测结果建立独立配置并重新引用。

## 五、平台账号管理

### 5.1 系统管理平台目录

账号授权采用固定平台目录和系统适配器。平台编号、官方授权入口、允许访问的地址、授权方式、身份识别逻辑、会话校验、信息字段和更新策略都由系统提供；普通用户只能选择已开放平台。

不保留“自定义平台”“任意登录网址”“手动粘贴 Cookie”“自定义账号身份”或随意增加识别字段的入口。候选平台必须通过完整接入验收后才可启用；未接通或失效时禁用入口并说明状态。

账号管理的“添加账号”使用居中弹框展示系统平台目录，每个选项包含平台官方图标、名称和可用状态。平台选项采用紧凑流式布局，按弹框可用宽度自动换行，不拉伸铺满整行，取消大面积卡片边框。点击已开放平台后进入授权流程；暂不可用的平台不允许选择。弹框支持关闭按钮、取消、退出键和点击遮罩关闭，关闭后保留账号列表及筛选状态，并恢复触发按钮焦点。弹框限制在主内容区，不遮盖左侧导航。

### 5.2 授权、保存和更新流程

1. 用户点击“添加账号”，从弹框中的图标和名称选择系统支持的平台，再选择独立浏览环境。
2. 服务端建立有有效期、一次性标识和归属校验的授权会话。
3. 客户端在正确隔离环境中打开系统规定的平台登录/授权入口；扫码、登录或平台验证由用户完成。
4. 系统适配器从平台读取稳定账号标识、昵称、头像和该平台实际允许的信息，并验证会话有效。
5. 服务端按团队、平台及稳定账号标识去重，安全保存授权凭据与版本，再返回账号详情。
6. 客户端刷新账号列表。只有身份确认、会话有效及服务端保存全部完成后，才能显示授权成功。
7. 后续通过平台允许的刷新方式或重新登录更新授权。到期时间未知时显示未知或需校验，不编造固定有效期。
8. 重新授权必须核对原平台账号标识。登录成其他账号时保留原记录与原有效凭据，并提供切回原账号或另行添加的操作。

取消、超时、网络失败、平台暂不可用、身份读取失败、身份不一致、保存失败、授权失效和权限不足都必须有独立状态。仅有 Cookie、能打开网页或关闭登录窗口，都不足以判定授权成功。

### 5.3 账号信息

所有账号的基础字段包括平台、稳定平台账号标识、昵称、头像、授权状态、所属环境、所属团队、最近校验与更新时间。平台特有字段仅在对应适配器真实返回并通过校验时展示；不伪造粉丝量、作品量、认证身份或授权时长。

账号列表提供添加授权、重新授权、校验/刷新、进入平台和移除授权等受控操作；不把发布、创作功能重新混入本轮范围。

### 5.4 当前接入证据

本轮直接查看的 `creator-hub/nodeservice-adapter.js` 仅列出微信公众号、抖音和新浪微博三个候选入口，并仍存在手动凭据、昵称兜底等旧逻辑。它们不等于已完成云端授权、加密保存和跨设备恢复。因此新稿平台页将这三个候选平台显示为不可用状态，不宣称已支持完整授权。

用户要求的目标流程参考蚁小二、融媒宝的固定平台账号管理方式；不是复制其未公开的内部实现。公开资料不足以确定完全相同的平台清单、授权时限或字段，实际支持目录必须以本系统逐平台接入与验收结果为准。

## 六、团队成员与权限

团队列表读取当前团队的真实成员。角色定义、模块操作权限和资源范围共同决定访问权。指纹、环境、代理和平台账号都必须进行团队隔离和对象级授权。

邀请与权限编辑不能授予超出操作者权限的资源；不能移除最后一名所有者或通过客户端参数提升角色。邀请状态、到期时间、撤销和接受结果从真实记录读取。

本版设计包含所有者、管理员、操作成员和只读成员四类系统角色；权限矩阵属于产品规则，实际授权由服务端执行。

## 七、订阅、用量与支付

### 7.1 国内支付

首期必须提供微信支付与支付宝扫码付款。用户选择套餐和周期 → 服务端报价与创建订单 → 选择支付渠道 → 生成真实支付码 → 查询支付结果 → 核验后开通或续期。

微信采用适用商户资质的 Native 下单能力；支付宝采用实际签约可用的扫码支付产品。商户、应用标识、签名密钥、证书、公网回调、套餐与正式价格均需要真实配置。

不生成假二维码、假订单或假付款成功，不在未配置时展示虚构套餐、价格、配额、到期日、用量进度或已购买权益。

### 7.2 订单与权益

支付适配层提供创建支付、查询、关单、校验通知及退款等窄接口。服务端核对订单归属、商户身份、金额、币种、状态和签名，使用幂等事务更新订单及订阅权益。

客户端只向业务服务端查询订单，不持有支付密钥。用户关闭付款页面不直接视为订单失败；支付成功与关单并发时重新核对最终状态。重复通知不能重复延长订阅或重复发放配额。

支持待支付、确认中、支付成功、已关闭、失败、退款中及已退款等真实状态。支付成功但权益更新未完成时显示处理中并重试，不要求用户再次付款。

### 7.3 国际支付扩展

保留渠道注册、支持币种、金额精度、支付会话、重定向/二维码、通知验签、退款和对账的扩展契约。未来国际渠道通过适配器加入，不能改写现有订单和权益规则；未配置的国际渠道不以“即将上线”空入口占据付款界面。

## 八、设置与无演示数据要求

设置仅包含个人账户、当前团队、登录设备、数据位置、恢复点、语言与动效、版本更新、服务连接及脱敏诊断。

交付要求：

- 页面不出现设计稿徽标、测试状态条、演示用户、演示团队、固定配额、示例账号或伪造状态；
- 列表无真实记录时呈现正常空状态，加载失败使用错误状态，不能以空列表吞掉错误；
- 真实生成前不显示二维码、平台身份、付款金额或代理出口；指纹初值复用现有系统默认配置，属于配置起点，不是已保存的业务记录；每份新草稿生成独立标识和噪声种子；
- 表单允许填写和保留草稿；无法连接真实服务时不模拟业务保存成功；
- 发布生产版本前清理现有客户端静态身份、伪造业务数据和服务端默认演示账号；初始化必须使用真实注册和团队创建流程；
- 应用发行包不携带设计画册、测试工具、示例业务记录或预置平台账号；
- 用户可见错误为简体中文，使用红色文字、图标和恢复操作，不直接暴露原始错误或敏感凭据。

## 九、视觉与导航规范

保留石墨色固定侧栏与明亮工作画布。主操作使用钴蓝 `#245EE8`，正文 `#18212D`、次级文字 `#6B7280`，错误 `#C5394C`。正文与表单按桌面可读尺寸设计，不以装饰性宣传卡片挤压业务操作。

导航是静态 HTML，包含工作台和七个业务模块的图标、中文标题、链接和路由属性。正常桌面窗口和高 DPI 下不静默隐藏标题；侧栏层级不低于 50。主要任务使用单页表单，长配置按指纹分类组织；弹窗与侧面板限制在内容区域，保留上下文。

### 9.1 2026-10-28 交互与密度优化

结合用户已登录的蚁小二账号页、授权弹框、环境编辑和代理添加界面的实际观察，收敛以下交互。只借鉴操作组织，不复制其平台数量、账号资料、套餐权益或业务数据。

- 全局：去掉交互稿内重复绘制的浏览器标签和地址栏，由真实宿主承载；工作空间顶部栏缩至 56 像素，标题为 22 像素，正文和操作文字以 13–14 像素为主。取消标题上方重复模块标签，减少连续卡片边框，使用中性灰正文与分隔线。
- 账号列表：按最新确认将平台统一放入列表工具栏下拉筛选，不在“全部平台”之后平铺各平台按钮；保留授权状态、所属环境及搜索，不在未加载数据时显示虚构数量。账号信息一列承载真实头像、昵称、平台图标和账号标识；昵称优先，稳定标识为次级文字。授权状态、所属环境和最近校验分别展示。常用操作直接可见，删除等低频操作进入更多菜单；无权限时明确说明原因。
- 平台选择：保留紧凑流式排列，不拉伸平台选项；平台是否可授权由真实接入状态决定。选择弹框关闭后保留平台筛选、搜索与列表状态。
- 授权流程：固定为“选择环境 → 平台登录 → 确认身份 → 保存授权”。进度标识只表明当前阶段，不凭前端跳转推断前序检查通过。选择平台后保留该平台；新建环境返回时保留授权上下文。取得平台身份之前不能手工补填账号资料，也不能保存。
- 授权恢复：增加等待平台登录、身份确认和保存失败界面。登录窗口关闭不代表成功；身份和会话校验不通过时禁止保存。保存失败保留上下文，重试前重新校验会话，通过幂等请求恢复保存，不重复添加账号。确认保存后仍须等待服务端响应，只有保存成功才返回账号列表并定位相应记录。
- 环境创建：基本信息、复用指纹、网络连接在一个表单内完成。直连时隐藏代理资源选择；切换为已有代理后再显示并检测。右侧摘要随名称等已填写内容更新，兼容性与时区检测必须等待真实结果，不通过输入动作伪造检查完成。
- 指纹配置：基础身份、语言和时区优先展示；硬件和屏幕、模块开关按需展开。展开状态和输入草稿在本次页面导航中保留，收起不表示参数可省略。保存前仍校验全部必需参数。
- 添加代理：从代理列表或环境创建页直接打开弹框，原页面不跳转。保留连接信息、可选认证、真实检测结果和底部操作；未检测或检测失败不能保存为可用代理。取消、退出键、关闭按钮和遮罩均恢复原页面焦点；草稿仅保留在当前页面会话内，不写入持久化存储。

新增三张授权条件状态图，总计 30 张高保真图。交互稿不提供模拟扫码、模拟身份或模拟保存成功；条件状态通过画册单独查看，正式操作由真实授权回调驱动。

### 9.2 最新确认：登录、默认参数与窗口布局

- 登录：顶部登录入口在当前页弹出邮箱和密码登录框，保持当前模块与表单草稿；支持退出键、遮罩、取消和关闭按钮，焦点回到触发位置。关闭时不缓存密码。登录成功须以服务端会话为准，设计稿不模拟登录成功。
- 默认参数：直接复用 `profile-store.js` 的默认配置与校验函数、`webgl-topology.js` 的硬件组合生成与拓扑检查。通过导出脚本生成浏览器可用的参数引擎，不维护第二套默认参数表。当前协议中的 138 是配置约束，不冒充设备实际运行时版本。
- 参数联动：平台变化联动显卡、线程数、内存、屏幕和独立噪声种子；主要语言变化联动语言列表与请求语言；生成操作产生新的自洽硬件组合。手动修改后检查可用屏幕范围、内存值、显卡后端与平台、语言优先级和用户代理版本／平台关系，冲突用红色说明。配置检查通过不等于设备兼容、指纹效果或运行时验收通过。
- 小窗口：以用户反馈的 1175×652 CSS 视口为常用密度目标；低高度下缩短导航行距、标题区、表单间距和空状态，完整保留八项导航图标与中文。多分类配置和设置采用分类切换，未选分类保持草稿；环境创建仍为一个短表单。工作台收紧任务卡片与最近环境空状态。长列表使用分页，长内容允许必要局部滚动，不以裁切或隐藏滚动条制造一屏假象。

### 9.3 指纹数据库保存契约

正式系统必须将指纹保存在服务端数据库，当前服务端的 `saas-db.json` 文件持久化不能作为该要求的完成证据。交互稿内存中的参数和草稿也不是已保存指纹。

建议沿用服务端选定的数据库与迁移机制，以以下两类独立资源实现，不与浏览器环境混存：

| 数据表 | 必需字段与约束 |
| --- | --- |
| 指纹资源 | 指纹标识、团队标识、名称、当前版本、创建人、修改人、创建和修改时间；查询与写入按团队及对象权限隔离 |
| 指纹版本 | 指纹标识、团队标识、版本号、协议版本、完整指纹配置、配置摘要、创建人和时间；指纹标识与版本号联合唯一；不保存代理、网址、Cookie 或运营信息 |

生成和修改配置后，客户端向服务端提交完整配置与预期版本。服务端再次执行结构、自洽与权限校验，通过同一数据库事务创建版本并更新当前版本；版本冲突返回可恢复的中文提示，不能覆盖他人更新。只有事务提交并返回实际资源标识与版本，界面才显示保存成功并刷新指纹列表。重试需去重，失败保留草稿。

环境保存指纹标识、已锁定版本和配置快照；新增指纹版本不改动已有环境。跨设备通过登录后的团队权限读取同一数据库记录，再检查设备与内核兼容性。数据库保存须验证重启后仍存在、另一设备可读取、其他团队不可访问，以及版本冲突和写入失败均不伪装成功。以上接口和迁移属于正式应用实施范围，本轮未把设计稿接入数据库。

## 十、本轮交付与实现边界

本轮依照原任务更新产品定义、页面结构、可点击稿和逐页高保真图，供确认后实施。图稿只使用配置字段、系统规则和正常空状态，条件性错误页不填造业务身份、时区或支付数据。

真实云端指纹库、服务端账号授权、代理检测服务、对象级权限、微信/支付宝和权益状态机仍需在正式应用中实现与验收。本轮界面设计不代表这些接口已经接通。
