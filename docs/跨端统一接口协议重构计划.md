# 跨端统一接口协议重构计划 (Bridge Protocol v2)

本文档作为桌面基座（`fingerprint-browser`）、业务前端/SaaS（`saas-server`）与平台能力（`media-platform`）之间接口协议重构的**唯一基准规划与状态跟踪文档**。

---

## 一、 核心架构原则与执行纪律

1. **函数签名恒定原则（Single Object Parameter）**：
   所有暴露的具名 API 方法签名永久固定为单一对象入参：`method(request = {})`。严禁位置参数，禁止基础数据类型（string / number）直接裸传。
2. **统一信封模型原则（Standard Envelope Pattern）**：
   严禁裸数据或平铺字段。同步返回统一使用 `ResponseEnvelope<T>`，异步长任务统一使用 `TaskEnvelope<T>`，广播推送统一使用 `EventEnvelope<T>`。业务载荷一律收归在 `data` 属性内。
3. **独立代码线原则（Isolated Pipelines）**：
   每个接口是一条自顶向下的独立管道（Preload 暴露 $\to$ IPC 路由 $\to$ 主进程专属 Handler $\to$ 底层原子操作）。各接口业务逻辑严禁交叉依赖或滥用共用抽象层，仅允许复用最底层的原子工具原语（如信封组装、加解密、Session 基础接口）。
4. **单接口闭环演进原则（Vertical Slice & Sync）**：
   以“单个接口”为独立改造单元。节奏严格遵守：
   $$\text{客户端实现新接口} \longrightarrow \text{SaaS端同步更新调用与消费} \longrightarrow \text{Dev环境端到端实际验证} \longrightarrow \text{清理客户端对应老接口与冗余逻辑} \longrightarrow \text{更新本文档状态}$$
5. **真实环境验收与诚实标记原则（Verification & Honesty）**：
   每个任务的合格标准为：**构建/启动客户端 Dev 环境，加载 SaaS 的 Dev 环境，跑通真实功能闭环**。可复用本地已有数据或创建必要测试数据。若遇客观限制（如必须真人手机扫码、物理硬件交互、外部受限凭据）无法自动闭环的，**严禁虚假打勾，必须明确标记为 `[?] 需要人工验证`**，并在备注中记录人工验收步骤。
6. **无指令不动业务代码原则**：
   后续开发严格根据用户明确下达的编码指令逐步推进，完成一个、验证一个、记录一个。

## 二、 标准信封结构规范

### 1. 同步响应信封 (`ResponseEnvelope<T>`)
```typescript
interface ResponseEnvelope<T = unknown> {
  ok: boolean;              // 业务成败标志
  code: string;             // 状态码：成功为 "SUCCESS"，失败为具体错误码
  message: string;          // 面向用户的简体中文提示信息
  data?: T;                 // 业务数据载荷（仅在 ok: true 时存在）
  timestamp: number;        // 响应生成毫秒时间戳
  traceId?: string;         // 链路追踪标识
}
```

### 2. 异步长任务信封 (`TaskEnvelope<T>`)
```typescript
type TaskStatus = 'pending' | 'running' | 'success' | 'failed' | 'cancelled';

interface TaskEnvelope<T = unknown> {
  ok: boolean;              // 任务状态正常标志
  taskId: string;           // 任务唯一全局 UUID
  type: string;             // 任务类型，如 "platform:authorize"
  status: TaskStatus;       // 状态机状态
  createdAt: number;        // 创建时间戳
  finishedAt?: number;      // 完成/终止时间戳
  expiresAt?: number;       // 缓存失效时间戳
  progress?: {              // 执行进度（可选）
    percent: number;        // 0 ~ 100
    step: string;           // 当前中文步骤说明
  };
  data?: T;                 // 成功产出的业务结果
  error?: {                 // 失败详情
    code: string;
    message: string;
    details?: unknown;
  } | null;
  timestamp: number;
}
```

### 3. 异步广播推送信封 (`EventEnvelope<T>`)
```typescript
interface EventEnvelope<T = unknown> {
  event: string;            // 事件标识，格式为 "domain:action"
  source: string;           // 发起源模块
  timestamp: number;        // 派发时间戳
  data: T;                  // 强类型事件快照载荷，保证为有效对象
}
```

## 四、 接口详细实施计划与改动规范

### 阶段一：系统与生命周期接口线 (`system`)

#### 任务 1.1: `system.getRuntime`
- **通道名称**：`system:get-runtime`
- **请求参数**：`{}`
- **响应信封**：`ResponseEnvelope<{ platform: string, chromiumVersion: string, environment: string, appName: string, protocolVersion: number }>`
- **客户端改造**：
  - 在 `desktop-preload.js` 增加 `desktopBridge.system.getRuntime`；
  - 在 `main.js` 注册独立 IPC handler，将数据收归在 `data` 属性内。
- **SaaS 端改造**：
  - `desktop-sdk.js` 映射 `workspaceBridge.system.getRuntime`；
  - 启动健康检查中读取 `res.data.protocolVersion`。
- **老接口清理**：
  - 移除原 `application:runtime` 通道及 `desktopBridge.runtime`。

#### 任务 1.2: `system.controlWindow`
- **通道名称**：`system:control-window`
- **请求参数**：`{ action: 'minimize' | 'maximize' | 'restore' | 'exit' }`
- **响应信封**：`ResponseEnvelope<void>`
- **客户端改造**：
  - 独立 Handler 校验 `request.action`，执行窗口相应操作并返回标准信封。
- **SaaS 端改造**：
  - 页面标题栏的窗口控制按钮切换为调用 `bridge.system.controlWindow({ action })`。
- **老接口清理**：
  - 移除原 `window:action` 接收基础字符串参数的旧处理分支。

#### 任务 1.3: `system.getUpdateStatus` & 任务 1.4: `system.checkUpdates` & 任务 1.5: `system.installUpdate`
- **通道名称**：`system:get-update-status` / `system:check-updates` / `system:install-update`
- **请求参数**：`{}`
- **响应信封**：`ResponseEnvelope<UpdateState>` / `ResponseEnvelope<UpdateCheckResult>` / `ResponseEnvelope<void>`
- **客户端改造**：
  - 分离 updater 各动作的独立返回值，状态统一包装入 `data`。
- **SaaS 端改造**：
  - `workspace.js` 的更新弹窗及检查逻辑从 `res.data` 中解构版本信息与下载进度。
- **老接口清理**：
  - 移除原 `updates:status`、`updates:check`、`updates:install`。

- **老接口清理**：

- **通道名称**：`tabs:select-v2`
- **请求参数**：`{ id: string }`（必须为对象）
- **响应信封**：`ResponseEnvelope<void>`（职责单一，不反向回传 snapshot）
- **客户端改造**：
  - 独立 Handler 验证 `request.id`，调用 `tabBrowser.select(id)`，成功返回标准信封。
- **SaaS 端改造**：
  - `workspace.js` 标签页点击事件由 `selectTab(id)` 改为 `tabs.select({ id })`。
- **老接口清理**：
  - 移除接受字符串参数的旧 `tabs:select`。

#### 任务 2.3: `tabs.close`
- **通道名称**：`tabs:close-v2`
- **请求参数**：`{ id: string }`
- **响应信封**：`ResponseEnvelope<void>`
- **客户端改造**：
  - 独立 Handler 验证 `request.id`，执行关闭并返回标准信封。
- **SaaS 端改造**：
  - `media-authorization.js`（154行）及 `workspace.js` 全量替换为 `tabs.close({ id })`。
- **老接口清理**：
  - 移除旧 `desktopBridge.closeTab`。

#### 任务 2.4: `tabs.navigate`
- **通道名称**：`tabs:navigate-v2`
- **请求参数**：`{ id: string, url: string, action?: 'load' | 'reload' }`
- **响应信封**：`ResponseEnvelope<void>`
- **客户端改造**：
  - 独立 Handler 处理导航。
- **SaaS 端改造**：
  - SaaS 端导航调用点适配单一对象入参。
- **老接口清理**：
  - 移除旧 `tabs:navigate`。

#### 任务 2.5: `tabs.create`
- **通道名称**：`tabs:create-v2`
- **请求参数**：`{ url?: string, managed?: boolean, capabilities?: string[] }`
- **响应信封**：`ResponseEnvelope<{ tabId: string }>`
- **客户端改造**：
  - 整合受控标签与普通标签创建，返回值装入 `data.tabId`。
- **SaaS 端改造**：
  - SaaS 创建标签处统一接收 `res.data.tabId`。
- **老接口清理**：
  - 移除 `tabs:ordinary` 及 `tabs:create-managed`。

#### 任务 2.6: `tabs.openDevTools` & 任务 2.7: `tabs.dashboard`
- **通道名称**：`tabs:open-devtools` / `tabs:open-dashboard`
- **请求参数**：`{ id: string }` / `{}`
- **响应信封**：`ResponseEnvelope<void>`
- **客户端改造**：
  - 独立 Handler 执行唤起。
- **SaaS 端改造**：
  - 对应的控制台唤起和返回仪表盘逻辑切换。
- **老接口清理**：
  - 移除对应老旧通道。

## 五、 单任务执行标准流程（SOP）

当您后续发出具体编码指令（例如“开始写代码，执行任务 1.1”）时，执行过程严格遵循以下标准化作业流程：

1. **核验现状**：阅读待改动接口的客户端源码与 SaaS 端消费源码，确认前置依赖与数据结构；
2. **客户端实现**：在 Preload 与 Main 中为该接口开辟独立处理线（入参强制为单一对象，出参强制为标准信封）；
3. **SaaS端同步切换**：修改 SaaS 端的对应调用（`desktop-sdk.js` 与业务页面），适配新参数与 `res.data` 结构；
4. **Dev 环境端到端实测验证**：
   - 运行客户端 Dev 环境与 SaaS Dev 环境；
   - 利用已有环境数据或生成测试数据，真实执行业务动作，验证数据流与界面响应闭环；
   - **自动化无法完成的边界处理**：如遇需真实微信/抖音扫码登录等客观无法自动化的场景，不得虚假标记为完成，必须将看板标记为 `[?] 需要人工验证`，并补充测试步骤说明；
5. **老接口下线**：确认新链路验证通过后，清理客户端对应的老接口通道与兼容代码；
6. **看板状态更新**：在本文档看板中将状态更新为 `[x]` 或 `[?]`，并记录完成时间与验证备注。
