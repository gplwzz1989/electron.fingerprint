本图规定平台能力与双端基座的目标依赖：网页调用客户端整合后的能力，不加载 platform 执行脚本；能力更新源由 SaaS 管理后台的独立发布接口提供，不依赖 SaaS 业务网页。SaaS 页面统一面向客户端 JSAPI 契约（`window.desktopBridge`）开发，PC 桌面基座与移动基座（`../electron.mobile`）分别在各自宿主中提供等价的原生能力映射，实现“一套 SaaS 前端代码，无缝运行于桌面与移动两端”。同时，客户端 JSAPI 暴露具有严格的宿主安全边界：特权桥接对象仅注入于受信任的 SaaS 业务页面与本地宿主 Shell；所有在指纹环境或独立标签中打开的第三方外部媒体平台页面（如抖音、小红书、快手、X 等）保持绝对静默，严禁挂载私有 JSAPI 或防检测特征变量，确保第三方页面的全局 `window` 与标准纯净 Chrome 100% 一致。

## 平台能力独立发布与动态加载流程（目标）

```mermaid
flowchart TD
    开发[修改独立 media-platform 的平台逻辑] --> 判断{已有桌面/移动桥接是否足够}
    判断 -->|是| 发布[递增版本并发布单个授权 JS 与完整性清单]
    判断 -->|否| 升级[按协议与内核边界扩展客户端能力并升级客户端]
    升级 --> 发布
    发布 --> 部署[发布到独立能力分发源]
    部署 --> 检查[客户端检查清单及宿主兼容性]
    检查 --> 加载[客户端校验并动态加载能力包]
    加载 --> 整合[客户端注册受控接口并管理任务与版本]
    整合 --> 网页[网页通过客户端桥接调用平台能力]
    网页 --> 交互[客户端执行平台交互与身份识别]
    交互 --> 核验[业务端校验任务归属并保存授权结果]
```

目标是平台能力独立于客户端安装包更新，由客户端提供稳定的网页调用接口；任务执行期间的版本保持及切换由客户端管理。SaaS 不负责平台脚本加载、平台执行或能力发布编排，网页不能要求客户端加载任意地址的代码。

发布与辅助查询以独立 Node.js 功能包为边界：media-platform 自行实现 HTTP、Cookie/代理、签名、素材读写/上传、平台路由、并发与任务状态，其他 Node 程序可直接调用。客户端只负责加载、凭据/素材输入封装、权限与桥接转换，不为包提供必需的 request/upload/调度宿主。当前授权 VM 与该目标不同，迁移及稳定函数签名见[六平台发布设计](多平台发布功能边界与接口协议.md)；旧授权流程仍按下节现状执行。

### 当前实现说明

网页仅调用客户端 JSAPI；Platform 与 RPA 由客户端分别校验、动态加载并在用户数据目录缓存。管理员上传 NCC 单 JS 后，后台原子递增版本并发布清单；客户端启动时自行更新，在途任务保持原版本。SaaS 不再打包平台身份核验 SDK，正式凭据通过 Prisma 保存到 platform_accounts。旧平台发布物需升级宿主契约，详见[客户端授权重构](客户端授权重构.md)。移动端基座对齐计划详见 [SaaS 移动端基座与双端 JSAPI 对齐实施计划](../electron.mobile/docs/SAAS_MOBILE_BASE_AND_JSAPI_ALIGNMENT_PLAN.md)。

## 环境与账号启动流程

```mermaid
sequenceDiagram
    actor 用户
    participant 网页 as SaaS 网页与桌面/移动 SDK
    participant 客户端 as 客户端基座 (桌面 / 移动)
    participant 服务 as SaaS 服务
    participant 数据 as MySQL
    participant 原生 as 原生隔离能力层 (Electron / Android ProfileStore)
    用户->>网页: 启动环境或打开账号
    网页->>网页: 检查桥接、协议及恢复能力
    网页->>服务: 检查服务健康与当前登录态
    网页->>客户端: prepareLaunch(scope, resourceId)
    客户端-->>网页: 请求标识、随机数、公钥
    网页->>服务: 携登录态与 CSRF 请求资源 launch
    服务->>数据: 校验权限与权益，读取环境及可用会话
    数据-->>服务: 资源数据
    服务-->>网页: desktop-launch-v1 加密信封
    网页->>客户端: launchEncrypted(requestId, envelope)
    客户端->>客户端: 校验调用页面、资源、时效及一次性消费
    客户端->>原生: 创建或复用隔离环境，配置指纹与代理
    opt 携带账号会话且满足恢复条件
        客户端->>原生: 首次访问前恢复 Cookie 与存储，或复用匹配的本机会话
    end
    原生-->>客户端: 环境启动结果
    客户端-->>网页: 标签标识或中文错误
    网页-->>用户: 展示实际结果
```

任一步校验失败应结束该次请求并反馈真实错误；普通网页模式缺少桥接时不执行本机启动。会话恢复的版本、来源、运行中标签限制以[公开协议](../fingerprint-browser/PROTOCOL.md)为准。

## 账号授权与会话保存流程（平台集成目标）

```mermaid
sequenceDiagram
    actor 用户
    participant 网页 as SaaS 网页
    participant 客户端 as 客户端 JSAPI (桌面 / 移动)
    participant 能力 as Platform 与 RPA
    participant 平台 as 媒体平台
    participant 服务 as SaaS 服务
    participant 数据 as MySQL
    用户->>网页: 选择平台与环境
    网页->>客户端: JSAPI 发送操作、团队、环境和平台
    Note over 网页,服务: 登录授权期间无 SaaS HTTP 请求或临时写库
    客户端->>客户端: 本地打开隔离环境和空白标签
    客户端->>能力: 执行平台规则与身份识别
    能力->>平台: 打开登录页并等待真实登录响应
    平台-->>能力: 登录身份与会话响应
    能力->>客户端: 采集并校验身份和会话
    客户端-->>网页: 仅成功结果通过 JSAPI 返回
    网页->>服务: 一次提交授权成功结果
    服务->>服务: 校验登录态、CSRF、权限、环境、身份和会话
    服务->>数据: Prisma 同事务写 platform_accounts 全部账号数据
    服务-->>网页: 返回保存结果
    网页-->>用户: 顶部显示成功或失败提示
```

取消、失败、超时或身份不完整时，流程在客户端结束，不调用 SaaS 保存接口，也不写授权中间数据。检测授权同样由客户端完成，只有客户端返回明确有效/失效结果后才调用账号检测接口更新状态。网页的环境列表属于工作空间正常预加载数据；新授权使用客户端已存在的本机环境配置创建隔离 Session。

平台能力包 0.2.3 提供新浪微博和微信公众号账号查询；客户端 0.4.2 在指定授权响应命中后读取当前隔离 Session Cookie，并调用 Node 能力包核验真实身份，不依赖页面 DOM。打开账号的密文携带原账号身份，更新时核对平台、身份与来源，成功后同步资料并递增会话版本；保存失败可通过手动保存重试。

## 开发新功能流程

```mermaid
flowchart TD
    需求[收到新功能需求] --> 阅读[先读工作空间说明、本流程及 AGENTS.md]
    阅读 --> 定位[追踪现有入口、数据所有权与调用链]
    定位 --> 分层{需求属于哪一层}
    分层 -->|业务或 SaaS 页面| 业务[修改 ../saas-server/src 或 public]
    分层 -->|平台逻辑且宿主接口可用| 平台[修改同级 media-platform，由客户端加载整合并向网页提供能力]
    分层 -->|桌面通用能力| 桌面[修改 fingerprint-browser，复用已有运行时]
    分层 -->|移动端基座与移动JSAPI| 移动[修改 ../electron.mobile，遵循双端一致 JSAPI 规范]
    分层 -->|跨项目协议| 协议[核对生产方、传输方、消费方及版本兼容]
    分层 -->|必须新增原生能力| 原生[读内核架构，核验既有缓存并做修改前预演]
    原生 --> 基线{缓存可复用且基线可解释}
    基线 -->|否| 停止[保留现场，报告阻塞；禁止全量编译]
    基线 -->|是| 局部[最小修改并仅同步内容实际变化的文件]
    局部 --> 预演[单文件检查与修改后预演，核对任务及失效原因]
    预演 --> 安全{新增任务是否均可解释}
    安全 -->|否或扩散超预期| 收窄[排查并收窄依赖；超过十步必须暂停排查]
    收窄 --> 预演
    安全 -->|是且完成必要排查| 编译[同目录最小目标增量构建，并发限制为四]
    业务 --> 验证[验证实际改动、关闭及无配置行为和必要隔离场景]
    平台 --> 验证
    桌面 --> 验证
    移动 --> 验证
    协议 --> 验证
    编译 --> 验证
    验证 --> 文档[同步关系、协议或流程中受影响的说明]
    文档 --> 交付[交付改动、验证结果及未验证事项]
```

跨项目协议需求仍需分别选择所属应用文件实施；协议变更不自动意味着需要原生编译。验证使用所属项目现有测试，涉及联调时分别启动真实服务与客户端；涉及交付包时另行核对压缩包清单及实际启动。本地检查、外部服务验收与生产验证须分别记录。

六平台图文动态发布的职责、统一入口、可配置并发及 SaaS—客户端—media-platform 协议见[多平台发布功能边界与接口协议](多平台发布功能边界与接口协议.md)。该文档为待实施设计，不表示现有授权宿主已经支持发布；发布业务任务与既有授权期间不写中间任务的规则分别适用。
