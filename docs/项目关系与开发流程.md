```mermaid
flowchart TB

    网页 -->|认证、CSRF、业务 API| 服务[NestJS SaaS 模块与控制器]
    服务 -->|持久化| 数据库[(MySQL 业务与加密会话数据)]

    平台[同级独立项目：media-platform] -->|独立发布单 JS 与版本清单| 资源[独立平台能力发布源]
    资源 -->|客户端获取与校验| 宿主[客户端平台能力加载与整合层]
    宿主 -->|受控能力接口| 桌面
    网页 <-->|desktop-sdk 与公开桥接协议| 桌面[桌面基座：fingerprint-browser]
    桌面 -->|加载配置首页| 网页
    桌面 -->|公开 Session API| 内核[定制 Electron：shell / lib]
    内核 -->|配置快照与跨进程适配| 能力[Chromium / Blink / V8 能力]
    补丁[patches / chromium_src] -.->|原生集成| 能力
    规范[fp-kernel 架构与参数规范] -.->|约束| 内核
    桌面 -->|维护| 本机[(本机隔离环境与会话)]

```

本图规定平台能力的目标依赖：网页调用客户端整合后的能力，不加载 platform 执行脚本；能力更新源由 SaaS 管理后台的独立发布接口提供，不依赖 SaaS 业务网页。SaaS 可以独立部署，桌面可接入其他符合公开协议的业务首页。客户端加载整合、后台版本发布及本机缓存已按 platform-runtime-v3 接入，具体实现与验收边界见[客户端授权重构](客户端授权重构.md)。

## 平台能力独立发布与动态加载流程（目标）

```mermaid
flowchart TD
    开发[修改独立 media-platform 的平台逻辑] --> 判断{已有桌面桥接是否足够}
    判断 -->|是| 发布[递增版本并发布单个授权 JS 与完整性清单]
    判断 -->|否| 升级[按协议与内核边界扩展客户端能力并升级客户端]
    升级 --> 发布
    发布 --> 部署[发布到独立能力分发源]
    部署 --> 检查[客户端检查清单及宿主兼容性]
    检查 --> 加载[客户端校验并动态加载能力包]
    加载 --> 整合[客户端注册受控接口并管理任务与版本]
    整合 --> 网页[网页通过桌面桥接调用平台能力]
    网页 --> 交互[客户端执行平台交互与身份识别]
    交互 --> 核验[业务端校验任务归属并保存授权结果]
```

目标是平台能力独立于客户端安装包更新，由客户端提供稳定的网页调用接口；任务执行期间的版本保持及切换由客户端管理。SaaS 不负责平台脚本加载、平台执行或能力发布编排，网页不能要求客户端加载任意地址的代码。

### 当前实现说明

网页仅调用客户端 JSAPI；Platform 与 RPA 由客户端分别校验、动态加载并在用户数据目录缓存。管理员上传 NCC 单 JS 后，后台原子递增版本并发布清单；客户端启动时自行更新，在途任务保持原版本。SaaS 不再打包平台身份核验 SDK，正式凭据保存到 auth_accounts。旧平台发布物需升级宿主契约，详见[客户端授权重构](客户端授权重构.md)。

## 环境与账号启动流程

```mermaid
sequenceDiagram
    actor 用户
    participant 网页 as SaaS 网页与桌面 SDK
    participant 桌面 as 桌面基座主进程
    participant 服务 as SaaS 服务
    participant 数据 as MySQL
    participant 内核 as Electron Session 与能力层
    用户->>网页: 启动环境或打开账号
    网页->>网页: 检查桥接、协议及恢复能力
    网页->>服务: 检查服务健康与当前登录态
    网页->>桌面: prepareLaunch(scope, resourceId)
    桌面-->>网页: 请求标识、随机数、公钥
    网页->>服务: 携登录态与 CSRF 请求资源 launch
    服务->>数据: 校验权限与权益，读取环境及可用会话
    数据-->>服务: 资源数据
    服务-->>网页: desktop-launch-v1 加密信封
    网页->>桌面: launchEncrypted(requestId, envelope)
    桌面->>桌面: 校验调用页面、资源、时效及一次性消费
    桌面->>内核: 创建或复用隔离环境，配置指纹与代理
    opt 携带账号会话且满足恢复条件
        桌面->>内核: 首次访问前恢复 Cookie 与存储，或复用匹配的本机会话
    end
    内核-->>桌面: 环境启动结果
    桌面-->>网页: 标签标识或中文错误
    网页-->>用户: 展示实际结果
```

任一步校验失败应结束该次请求并反馈真实错误；普通网页模式缺少桥接时不执行本机启动。会话恢复的版本、来源、运行中标签限制以[公开协议](../fingerprint-browser/PROTOCOL.md)为准。

## 账号授权与会话保存流程（平台集成目标）

```mermaid
sequenceDiagram
    actor 用户
    participant 网页 as SaaS 网页
    participant 客户端 as 客户端 JSAPI
    participant 能力 as Platform 与 RPA
    participant 平台 as 媒体平台
    participant 服务 as SaaS 服务
    participant 数据 as MySQL
    用户->>网页: 选择平台与环境
    网页->>客户端: JSAPI 发送操作、团队、环境和平台
    Note over 网页,服务: 登录授权期间无 SaaS HTTP 请求或临时写库
    客户端->>客户端: 本地打开隔离环境和空白标签
    客户端->>能力: 执行平台规则与身份识别
    能力->>平台: 打开登录页并等待真实登录响应
    平台-->>能力: 登录身份与会话响应
    能力->>客户端: 采集并校验身份和会话
    客户端-->>网页: 仅成功结果通过 JSAPI 返回
    网页->>服务: 一次提交授权成功结果
    服务->>服务: 校验登录态、CSRF、权限、环境、身份和会话
    服务->>数据: 同事务写 auth_accounts 全部账号数据
    服务-->>网页: 返回保存结果
    网页-->>用户: 顶部显示成功或失败提示
```

取消、失败、超时或身份不完整时，流程在客户端结束，不调用 SaaS 保存接口，也不写授权中间数据。检测授权同样由客户端完成，只有客户端返回明确有效/失效结果后才调用账号检测接口更新状态。网页的环境列表属于工作空间正常预加载数据；新授权使用客户端已存在的本机环境配置创建隔离 Session。

## 开发新功能流程

```mermaid
flowchart TD
    需求[收到新功能需求] --> 阅读[先读工作空间说明、本流程及 AGENTS.md]
    阅读 --> 定位[追踪现有入口、数据所有权与调用链]
    定位 --> 分层{需求属于哪一层}
    分层 -->|业务或 SaaS 页面| 业务[修改 saas-server/src 或 public]
    分层 -->|平台逻辑且宿主接口可用| 平台[修改同级 media-platform，由客户端加载整合并向网页提供能力]
    分层 -->|桌面通用能力| 桌面[修改 fingerprint-browser，复用已有运行时]
    分层 -->|跨项目协议| 协议[核对生产方、传输方、消费方及版本兼容]
    分层 -->|必须新增原生能力| 原生[读内核架构，核验既有缓存并做修改前预演]
    原生 --> 基线{缓存可复用且基线可解释}
    基线 -->|否| 停止[保留现场，报告阻塞；禁止全量编译]
    基线 -->|是| 局部[最小修改并仅同步内容实际变化的文件]
    局部 --> 预演[单文件检查与修改后预演，核对任务及失效原因]
    预演 --> 安全{新增任务是否均可解释}
    安全 -->|否或扩散超预期| 收窄[排查并收窄依赖；超过十步必须暂停排查]
    收窄 --> 预演
    安全 -->|是且完成必要排查| 编译[同目录最小目标增量构建，并发限制为四]
    业务 --> 验证[验证实际改动、关闭及无配置行为和必要隔离场景]
    平台 --> 验证
    桌面 --> 验证
    协议 --> 验证
    编译 --> 验证
    验证 --> 文档[同步关系、协议或流程中受影响的说明]
    文档 --> 交付[交付改动、验证结果及未验证事项]
```

跨项目协议需求仍需分别选择所属应用文件实施；协议变更不自动意味着需要原生编译。验证使用所属项目现有测试，涉及联调时分别启动真实服务与客户端；涉及交付包时另行核对压缩包清单及实际启动。本地检查、外部服务验收与生产验证须分别记录。
