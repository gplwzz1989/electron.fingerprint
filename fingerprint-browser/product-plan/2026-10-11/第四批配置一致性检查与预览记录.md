# 第四批配置一致性检查与预览记录

本批推进 F-03 的保存前组合约束、提交值调整预览及新建草稿默认策略。上一批成果已在提交 `ee38006` 推送到 `origin/fp/37.2.6`。

## 实现范围

- 新增应用层 `fingerprint-review.js`，复用现有字段校验与保护范围说明；由主进程提供真实宿主系统和运行时完整版本，页面不能自行声明宿主能力。
- 检查浏览器主版本、用户代理主版本、启用客户端提示时的完整版本与桌面系统、设备平台与真实宿主、语言列表首项与请求语言最高有效权重、非 Windows 宿主上的 Direct3D 名称。原生缩减版本保留支持；关闭配置或对应模块时不限制未生效的表面。
- 创建、环境编辑增加“检查配置组合”和可见结果；实际保存自动复查，主进程保存接口再次检查，直接调用接口不能绕过。
- 预览返回内存提交值的前后差异，不写配置、不改变原草稿或种子；用户取消调整时不继续保存，确认后提交 8 GiB。直接提交 16 GiB 会被拒绝。确认提示也展示已配置保护中的风险。
- 保留原有旧文件读取自动兼容逻辑，不新增启动时组合拒绝。环境指纹没有修改时不随元数据编辑重新提交。保存队列、版本冲突、原子写入、会话锁定和稳定种子规则沿用已有实现。
- 仅新建草稿默认启用非代理 UDP 限制；macOS/Linux 新草稿使用对应宿主平台并保留原生图形名称，避免套用 Windows 的图形后端。没有批量修改旧环境或开启现有 Canvas/音频噪声。

## 验证与边界

- 基础自检覆盖真实与缩减版本、版本/系统/语言冲突、权重及大小写规范化、关闭配置/模块、三类宿主规则、预览不改原值及保存拒绝。macOS/Linux 为规则模拟测试，未在这些系统运行真实客户端。
- 统一标签回归增加真实 IPC 只读预览、拒绝保存后文件不变、环境编辑拒绝后快照不变，以及向导冲突展示和创建阻断。内存调整确认在真实页面中模拟取消/接受响应，核对确认文案、返回值与原草稿不变；没有自动点击真实系统确认窗口。
- 本批只修改应用层 JavaScript、测试和文档，复用 `J:\awork\electron-fp-build\src\out\Release` 运行时。没有原生源码变更、Ninja 构建、运行时 ZIP 更新或发行打包。

验收结果：`npm test` 通过；`npm run test:tabs` 十七阶段通过，结果为 `dist/electron-diagnostics/tabs/result.json`；`npm run test:environments` 跨进程环境、指纹、Cookie 和本地存储恢复通过。拒绝保存、错误认证及应用退出日志来自预期负向测试。

本地常规远端拉取因工具检查点引用指向缺失对象而失败；未删除这些引用或重置源码。通过直接读取远端分支提交确认起点与本地一致后，正常快进推送成功。该本地引用问题仍需独立排查。

这些约束只发现已知配置矛盾，不证明 GPU 扩展/精度/limits、CPU 架构、字体渲染或整个环境身份一致。语言与时区不按 IP 自动修改。

提交值调整预览不等于旧文件批量迁移完成：旧文件原始 16 GiB 的可见清单、原始字节备份、显式应用和回滚仍待实现。可信图形模板、完整保护模式、后台工作线程提示、可信站点密钥、Canvas 跨站相同及静音音频固定偏移继续按计划推进。非代理 UDP 限制可能影响实时通信，已保存环境不会自动改变。
