# Electron 指纹内核现状分析与下一步开发计划

日期：2026-10-13。分析基线：`e0f8a11029bbf30482609812e57be6851c9d67a2`，当前 Windows 本地多环境产品及已有 Electron 37.2.6 自定义运行时。

## 1. 结论与本期目标

项目已有可用的 Session 配置、独立环境目录、恢复机制、多个原生指纹挂接点和受控诊断入口。下一阶段的重点是补齐“配置输入 → 原生生效 → 实际行为 → 发行验收”的闭环，优先处理已有失败和入口绕过，再扩展能力。

建议以一个“小版本可靠性收敛”为本期目标：自动化入口与界面执行相同规则；中文配置可靠传输；WebGPU 策略实际生效；已知失败进入发布门禁；页面与后台线程、代理与存储隔离获得明确的验证范围。保留现有架构，不启动全库重构。

本文承接 [10 月 11 日总体方案](../2026-10-11/主流指纹浏览器技术分析与指纹强化防关联开发计划.md)，按后续提交和运行证据调整顺序。此前已完成的配置预览、页面客户端提示协商、Canvas 域名参与扰动、音频非恒定扰动不重复立项。

### 2.2 当前最需要解决的问题

| 优先级 | 发现 | 证据状态及限制 |
| --- | --- | --- |
| P0 | WebGPU 关闭策略未达到预期，仍能取得实际适配器信息 | 历史专项实测：会话策略、应用全局策略下均可取得适配器，返回 `intel / gen-9`。不是仅凭源码推测 |
| P0 | 非 ASCII 配置传输存在缺口 | 历史中文种子音频验证失败、ASCII 种子通过；本次源码确认 `GetSwitchValueASCII` 遇非 ASCII 返回空串。多个 Blink 消费端用该接口读整份 JSON，完整影响范围待回归 |
| P0 | 本地自动化服务没有鉴权，且允许任意来源的跨域请求 | 源码确认：启动阶段默认启动服务；请求入口未检查凭据，CORS 为 `*`，支持创建、启动、停止、删除；列表/详情直接展开环境对象，含代理配置。浏览器侧具体可达性受本地网络访问策略影响，未做外部攻击测试 |
| P0 | 自动化保存绕过已有配置组合检查 | 本次纯内存调用确认：Windows 的 Apple/Metal 图形配置被预览拒绝，但 REST 创建处理函数接受。该结果证明保存入口不一致，不声称已验证其所有运行表现 |
| P1 | “创建环境”接口实际先保存配置，模板 ID、环境 ID 与更新语义混合 | 本次内存核验：同一预设不传 ID 连续创建两次，返回相同 ID，仓库只剩后一名称的记录且修订号变为 2。创建后未启动的记录也不来自环境列表所用仓库 |
| P0 | 常规检查成功不能代表保护可发布 | 历史报告为 `ok: true`、`protectionReady: false`、零项 `gaps`，同时有十一类未验证；独立 WebGPU 专项仍失败。现有运行测试按断言失败决定退出状态，未把保护就绪要求作为独立发布门槛 |
| P1 | Worker 请求的高熵客户端提示和完整表面尚未闭环 | 历史报告将两个保护环境的 dedicated/shared/service Worker 请求协商分别记为未完成；不能直接判为已发现全部 Worker 泄漏 |
| P1 | 文档、自动检查和实际能力状态不一致 | 部分能力文档仍写待编译或旧音频策略；`fp-validate.yml` 目前运行版本检查、补丁基础文件存在检查及两个 JSON 解析，不等于 Schema 语义、补丁适用性或运行回归 |

已排除的误判：实际环境创建会重新生成种子，不能据预设固定种子断言环境共用种子；`TabBrowser.open()` 返回真实环境 ID，且展开结果覆盖接口中的配置 ID，不能断言启动响应一定返回错误 ID。仍需修复创建/更新/重复启动的契约与测试。

## 3. 分批交付计划

### 第一批：统一应用入口与发布判定

这批只改应用、测试和轻量检查，复用现有运行时，可在原生问题排查期间先完成。

| 编号 | 任务与最小落点 | 验收标准 |
| --- | --- | --- |
| A1 | 在 `automation-server.js`、`main.js` 加入本地自动化的显式启用设置与访问凭据；默认约束回环监听，限制允许来源与 Host；列表/详情默认不返回代理密码；保留原有模块结构 | 未授权请求不能读环境或执行写操作；有效凭据可完成已有操作；不可信来源被拒绝；无 Origin 的合法本地脚本仍可使用；响应和日志不暴露凭据 |
| A2 | 自动化创建/修改复用 `fingerprint-review.js` 的保存检查；运行时事实由主进程提供，禁止请求自报宿主；在写入之前校验 | 与界面相同的合法/非法配置得到相同结果；拒绝后配置、环境目录及分组均无意外写入；关闭模块遵循既有规则；不改变旧环境启动兼容策略 |
| A3 | 明确配置模板与环境实例契约：创建默认生成唯一 ID，显式更新检查修订号；创建、列表、详情、启动、停止、删除使用一致的实例语义；保持已有调用兼容并给出清晰返回字段 | 同预设连续创建得到独立记录；实际环境种子不同且重启稳定；按返回实例 ID 可完成整个生命周期；重复请求按声明的语义处理，不意外覆盖配置或增开环境 |
| A4 | 扩展 `test/automation-server.test.js`，保留快速单测，增加真实仓库和真实环境生命周期集成用例；禁止 mock 将配置 ID 当成环境 ID | 覆盖 A1～A3；启动失败后仍能用已创建实例 ID 查询、恢复或清理；文件写入与失败恢复语义可核验 |
| A5 | 在现有指纹测试报告中区分通过、失败、未测试、不适用；针对本期声明能力设独立发布必测清单；先纳入已有 WebGPU、中文种子和非静音音频反例 | 必测项失败、未完成或缺证据均不能发布为“保护已就绪”；非必测探索项单独列出；报告不再以零 `gaps` 代替合格结论 |

A1 的范围是当前具体暴露的本地控制接口，不引入账号系统或通用权限平台。A3 需先补契约测试再最小修改，不重写仓库；保存配置成功与环境真正启动成功必须分别返回。

### 第二批：修复 Electron 到 Blink 的生效链路

#### N1：非 ASCII 配置完整传输

- 层级与落点：Electron 的 `electron_browser_client.cc` 序列化出口，以及现有 Chromium/Blink 补丁中读取 `fingerprint-config` 的消费者。先枚举全部生产、传输、解析路径。
- 当前证据：生产端 JSON 通过 `AppendSwitchASCII` 传入；本机该函数内部转用 UTF-8 写入，而消费端 `GetSwitchValueASCII` 对非 ASCII 返回空字符串。优先检查并统一既有 UTF-8 读取契约，不新建跨进程协议，也不修改 Chromium 通用命令行函数的行为。
- 变更前说明：优先只改相关 `.cc` 和对应补丁；不改公共头、Schema、GN。该问题横跨多个消费单元，不能保证小于十步；按实际依赖评估，不为降低数字遗漏消费者。
- 验收：中文环境字段、中文字体及种子、混合 Unicode、转义字符、非法输入；页面和受支持 Worker 的配置有效；同环境稳定、不同环境隔离；无配置/总关闭/模块关闭回退不变。加入合法配置往返一致性与错误反馈测试。
- 构建：沿用 Release，对实际涉及目标做前后预演；超过十步先排查共享头和依赖扩散，确认均为必要依赖后才推进。

#### N2：WebGPU 策略真正生效

- 第一目标是落实可验证的保护策略，建议先做“启用相应保护时阻断 WebGPU 设备访问”，并在产品中说明兼容影响；完整 GPU 身份模拟另立后续能力。
- 先查 Chromium 当前版本实际控制入口、Blink 运行时特性与 GPU 进程检查点，核对 FeatureList 初始化时序和多处 `disable-features` 合并行为。已有参数未生效，不直接认定某个替代开关即可修复。
- 优先落点是 `electron_browser_client.cc` 及必要的 WebGPU 私有 `.cc` 接入点；`main.js` 的全局设置要与 Session 范围统一。若最终只能全进程限制，明确说明其作用范围，并评估对未保护环境的影响，不能伪称会话隔离已实现。
- 验收：在支持 WebGPU 的设备和安全上下文中，无配置对照确实可用；受保护页面及受支持 Worker 无法取得适配器/设备；两类环境同时运行不互相污染；总开关及模块开关符合声明。检查 WebGL、Canvas、图形页面兼容与硬件加速是否受意外影响。
- 不仅检查 `navigator.gpu` 是否存在，必须实际请求 adapter/device，记录可见属性与运行结果。能力不支持的设备记为不适用，不能拿空结果作为有效阻断证据。
- 构建预期：Electron 适配单元及确有必要的 Blink/GPU 私有实现与最终链接；实际 GN 目标、步骤和失效原因以预演为准。

N1、N2 分开提交和回归，以便定位、回滚；不要混入版本升级、图形参数全面改造或架构重构。

### 第三批：后台上下文、生命周期与网络证据

| 编号 | 重点与实现边界 | 验收标准 |
| --- | --- | --- |
| V1 | 高熵客户端提示：复用 `electron_browser_context.cc` 中现有 Session 委托和来源缓存；先验证 Worker 自身请求的协商过程，再定位缺口 | 页面与 dedicated/shared/service Worker 记录首次请求、Accept-CH 响应及后续请求头；同一 Session 按契约共享、不同 Session 不串用；明确持久化与重启预期 |
| V2 | 生命周期和存储：扩展已有环境恢复及指纹诊断，不新增 Session 管理器 | A/B/C 环境同时运行、关闭一个、崩溃恢复、客户端重启、后台 SW 唤醒、跨站 iframe；不互读 Cookie/存储/权限，种子与配置稳定 |
| V3 | 完整代理矩阵：复用既有代理入口、本地 SOCKS5 桥和受控网络夹具 | HTTP/HTTPS/SOCKS5、认证成败、中途断线及恢复、下载/媒体/Worker/WSS；同时记录端点来源和网络证据，代理故障不隐式直连 |
| V4 | DNS/IPv6/QUIC/WebRTC：先提供可达且可观测的双栈、STUN/TURN 测试环境，再决定是否需要原生改动 | 区分代理基础设施解析与目标解析；无非预期目标直连；STUN/TURN 不可达属于未测试；会议兼容单独验收 |

第三批的夹具和采集先在应用层完成。只有证据指向原生缺口才增加局部原生任务。已有页面提示协商及受控代理故障测试继续保留，不能每轮从零重写。

### 第四批：完善高熵表面与可信预设

1. **Canvas**：回归现有站点扰动改动，覆盖读取子区域、透明/纯色、重复读回、导出、OffscreenCanvas 及可用 Worker；确定嵌套 iframe、跨站第三方与导航后的分区契约。不能仅以两个哈希不同宣布不可关联。
2. **Audio**：保留已修复的非恒定噪声与采样率语义；增加静音、非静音、多声道、不同采样率、重复渲染及简单差分恢复实验。验证有限实验能抵抗什么，不宣称通用不可恢复。
3. **WebGL/字体/几何**：核对各读回格式、扩展、精度、limits、字体回退、测量结果与排版；检查配置字符串与真实能力的矛盾，先修可复现旁路。
4. **预设兼容范围**：三个设备预设按宿主、内核和实测能力分级；默认提供可验证组合。当前 Windows 配置校验不能证明 NVIDIA 模型、字体或其他系统渲染都被还原，不承诺跨系统完整模拟。
5. **旧环境迁移**：延续已有内存预览，补原始配置备份、变更清单、显式应用和单环境回滚；新算法/模板更新不能静默轮换已有身份。

优先扩展现有 `fingerprint-probes.js`、`fingerprint-isolation.test.js` 和既有补丁。按照受影响能力逐项交付，不新建统一指纹框架，不为各业务开关新增全局编译宏。

## 4. 架构与构建执行约束

按照 [内核架构](../../../fp-kernel/docs/ARCHITECTURE.md) 维持单向链路：应用配置 → Electron 校验和会话快照 → 跨进程适配 → Chromium 能力执行。业务和存储留在应用层，Chromium 不反向依赖 Electron 业务头文件。

| 任务类型 | 构建边界 |
| --- | --- |
| A1～A5、测试夹具、文档和预设 | 复用现有运行时，无须 Chromium/Electron 原生编译 |
| N1 | 对应配置消费 `.cc` 的必要编译及链接；跨模块数量较多，预演后才能估计实际成本 |
| N2、V1 的必要修复 | 优先现有 Electron `.cc`，仅在现有接口不能实现时增加所属模块私有接入点 |
| 第四批原生能力 | 每个能力先列挂接点、调用方、目标和预期依赖，再单独进入原生流程 |

原生执行必须复用 `J:\awork\electron-fp-build\src\out\Release`。核验缓存、工具链和并发任务；修改前后记录 Ninja 预演及失效原因；超过十步暂停排查；新增任务均能解释后，以 `-j 4` 构建最小目标。运行时 ZIP 单独预演与执行。

只同步内容确有差异的源码，保留构建副本已有修改；禁止全树复制、补丁全量重放、清缓存、重新同步依赖、变更配置或以新目录变相全量编译。实际出现预演无法解释的大范围任务时安全停止。

每个修改的 `.cc` 应执行规定的 `check_cpp_syntax.py` 单文件检查；前次在本机未找到该脚本，实施时先解决工具定位或明确记录检查缺失，不能以历史编译成功代替该检查。

## 5. 发布与工程维护

- **证据绑定**：每份结果记录应用提交、实际原生差异清单、运行时与发行包 SHA-256、配置摘要、宿主、启动方式及时间。构建副本 HEAD 较旧且有定向同步修改，单看 Git 提交不足以识别真实运行时。
- **检查分层**：轻量 CI 加入应用基础测试、真正的 Schema 校验及补丁清单一致性检查；运行验证使用已核验的自定义运行时。不得让轻量检查隐式触发新机器全量原生构建。
- **发布门槛**：本期必测清单先覆盖 A1～A5、N1/N2、关键环境隔离和现有网络回归；未达标则不宣称这些能力已交付。公网完整防泄漏等扩大声明必须等待对应矩阵完成。
- **发行验证**：复测实际便携包及适用的安装流程，核对进程退出、数据目录和环境恢复。上次启动首次超时、重试成功只说明重试通过，启动时序根因仍需日志诊断，不能标为已修复。
- **文档同步**：更新 `PATCH_REGISTRY.md`、`FINGERPRINT_POINTS.md`、`TESTING.md`，分别标明已实现、已编译、已运行验证、发行已包含、未覆盖范围。
- **安全维护评估**：单独核对 Electron 37.2.6 所用上游的安全修复和维护状态。本次没有在线核验最新公告，不给出当前支持状态断言；需要换上游或工具链且不能复用缓存时，提交兼容性和迁移方案，不能自动开始全量构建。

## 6. 建议执行顺序与完成定义
