依据用户提供的三张参考图：浏览器行为参考前两张，品牌、标签与侧栏的视觉语言参考上一版栖界。当前交付用于外观确认，未修改正式客户端，未执行新的打包。

## 三类标签与关键状态

1. 首页：固定的首页标签、只读真实 SaaS 地址、八项导航、团队切换和业务管理内容。当前以未登录空状态呈现，不编造个人姓名、团队、账号、统计或环境记录。
2. 点击“＋”创建的普通标签：直接打开普通新标签页，地址栏可输入网址，无需登录 SaaS 或先选择环境；整个内容区显示当前网页，没有 SaaS 导航或强制的环境选择步骤。
3. SaaS 系统创建的标签：由账号、环境等业务操作创建，使用系统指定的网页与会话配置；可开放哪些客户端能力由 SaaS 按标签指定，并由客户端主进程执行授权校验。

普通标签与系统创建标签外观沿用浏览器标签结构。预览的“系统创建标签”按钮位于评审栏，只用于检查这一状态，不是新增的产品入口。正式产品仍通过 SaaS 内的账号、环境等操作创建。

- “＋”直接新建普通网页标签，地址栏自动获得焦点；不拦截为环境选择或创建流程。其他标签支持切换和关闭。

## 客户端能力边界

| 标签创建来源 | 页面访问 | 客户端业务 API |
| --- | --- | --- |
| 客户端启动时固定创建的 SaaS 首页 | 打包配置确定的 SaaS 页面及其正常内部路由 | 完整业务桥接能力，仍校验每个业务操作的登录、团队和资源权限 |
| 用户点击“＋”创建 | 普通网页浏览，可直接输入网址 | 不自动注入原生桥接；可持有效令牌访问本地 HTTP API，不限制来源；访问同一 SaaS URL 不会自动提权 |
| 可信 SaaS 页面通过客户端业务接口创建 | 系统指定的账号、环境或其他任务页面 | 按 SaaS 明确指定的能力配置开放，可按任务配置；不能仅因“系统创建”就隐式继承所有权限 |

主进程根据实际创建调用来源登记标签类型和能力授权，不能相信网页提交的 `createdBy`、`isTrusted` 等字段，也不能只凭 URL 判断权限。SaaS 业务可以为自己创建的标签指定空能力集合、部分能力或完整业务能力，并按业务需要更新或撤销；客户端在每次内部调用时核验实际 WebContents、调用框架、能力范围和业务权限。网页不能自行扩大授权。

导航、重定向、子框架、弹出窗口和关闭后的授权生命周期需要单独处理：固定首页不能被替换到第三方站点；普通网页创建的弹窗不继承 SaaS 权限；系统创建标签按 SaaS 指定的来源和能力策略重新校验跨站导航；关闭即撤销授权。固定首页拥有完整客户端业务能力不等于向网页暴露任意文件系统、原始 IPC 或 Node.js 全局权限。

设计预览没有真实客户端桥接，不将标签状态演示当作正式客户端的能力隔离验收。后续正式实现与实际验收说明见 `../../CLIENT-SHELL.md`。本地 HTTP 按用户最终要求仅校验令牌，不限制来源；固定 SaaS 与系统授权标签由主进程代管令牌，免手动鉴权。

后续实现必须覆盖：普通标签访问相同 SaaS URL 不提权；网页伪造标签来源或能力字段不能提权；系统创建标签只可调用获准能力，授权更新与撤销即时生效；子框架和弹出窗口不能继承来源标签的内部权限；关闭后原标签身份及授权不可再用。所有操作继续执行现有团队、账号和环境范围检查。
