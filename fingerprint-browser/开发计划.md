# 指纹浏览器开发计划

更新时间：2026-10-03

## 目标与边界

将现有多标签验证项目完善为可长期使用、可接入现有 Node.js 项目的指纹浏览器。
优先保证配置和登录数据可靠，再完善网络隔离、网站兼容性、性能与交付。

- 指纹接口继续接收 JSON 对象，不要求调用方创建配置文件。
- 每个独立环境使用独立绝对数据路径、Session 和指纹快照。
- 同一配置可以创建多个环境，但不同环境不共享 Cookie、缓存和会话。
- 配置更新只作用于新环境；恢复旧环境使用原指纹快照，不热更新已锁定 Session。
- 不修改无关 Electron/Chromium 源码，不干扰正在运行的内核构建。
- 保留中文注释，使用 UTF-8、中文界面和中文错误提示。
- 复用现有实现与原生能力，第一阶段不增加依赖；具体数据库未明确前不擅自选型。
- 不承诺所有指纹点均已生效，也不将测试产物视为正式发行包。

## 当前基线

- 已实现配置增删改、多标签导航、独立 Session 和目录。
- 已有多标签实测覆盖部分页面指纹以及 Cookie、本地存储、会话存储、数据库和缓存隔离。
- 应用配置仍使用 `profiles.json`，内核接收解析后的 JSON 对象。
- 已有独立环境列表、关闭后重开和跨进程退出恢复；环境记录与配置记录分开保存。
- 网站弹窗默认拒绝；暂无应用层独立代理、下载与权限管理。
- 内核基线为 Electron 37.2.6 / Chromium 138；能力必须以实际运行时探测和回归结果为准。

## 阶段与验收

### 第一阶段：数据可靠性与输入校验（已完成）

- [x] 保留原配置文件格式，改为同目录临时文件写入、同步和重命名提交。
- [x] 保留上一份有效配置备份；损坏时读取有效备份并提示，保留损坏原文件。
- [x] 配置修改串行执行，写入成功后才提交内存状态，失败不污染内存。
- [x] 配置更新检查版本冲突，过期编辑不能静默覆盖新版本。
- [x] 同一应用数据目录只允许一个实例；正常退出等待已接受的配置写入。
- [x] 校验有效时区、语言标记、有限缩放值和原生整数范围，保持对象入参不变。
- [x] 管理页补充内容安全策略。
- [x] 增加并发保存、失败恢复、备份读取、冲突及非法输入测试。
- [x] 使用真实 Electron 回归多标签隔离与配置保存接口。

验收：并发修改不丢记录；写入失败时原文件与内存保持原值；队列失败后仍可继续保存；
有有效备份的损坏文件不会重置为默认配置；无可用备份时明确报错而非覆盖数据；原多标签测试不退化。
重命名与文件同步降低进程中断风险，但不承诺所有文件系统上的断电绝对安全。

### 第二阶段：环境管理与恢复（已完成）

- [x] 建立环境记录，包含环境 ID、来源配置 ID/版本、目录、指纹快照、最近网址与状态。
- [x] 明确区分“新建独立环境”和“重新打开已有环境”，避免复用配置 ID 导致会话共享。
- [x] 增加环境列表、关闭后重开、跨进程退出恢复。
- [x] 同一环境禁止并发打开；恢复失败可重试，不删除 Cookie 或改换指纹。
- [x] 支持明确确认后的环境删除；只清理已验证属于应用的指定目录，Windows 目录锁定时延迟清理。
- [x] 关闭应用前保存环境状态并刷新 Cookie；处理浏览器窗口关闭、标签关闭和 Session 复用竞争条件。

验收：重启后能够恢复相同目录、指纹和登录数据；不同环境仍隔离；修改模板不改变旧环境；
目录丢失、配置损坏、页面崩溃均有中文提示及安全恢复路径。删除被 Windows Session 锁定的目录时，
先从环境列表移除并在后续启动清理，不强制删除正在使用的文件。

- [ ] 扩充页面、请求头、普通 Worker、ServiceWorker 和跨域 iframe 一致性测试。

### 第四阶段：网络隔离与网站兼容（待实施）

- [ ] 制定弹窗规则：授权登录弹窗使用来源环境会话，新建独立环境不复用会话。
- [ ] 增加按环境归属的下载列表、保存位置选择和取消操作。
- [ ] 摄像头、麦克风、定位、通知等权限按环境和来源确认；不默认允许所有权限。
- [ ] 保持证书校验，不以全局忽略证书错误解决访问问题。

验收：两个环境可使用不同代理；认证不串环境；登录弹窗可正常完成且不越权；
拒绝权限、下载失败和代理断开有明确提示。

- [ ] 启动时显示实际内核版本及能力；区分源码状态与已构建产物状态。
- [ ] 制定 Chromium 安全更新和补丁迁移流程。
- [ ] 使用完整正式运行时制作安装包，验证数据目录可写、升级迁移及卸载数据保留策略。
- [ ] 完成发行签名、回退方案及使用说明；经用户要求后提交并推送相关修改。

验收：安装后无需本机源码目录即可启动；升级不丢配置和登录数据；回归记录可追溯到运行时版本。

## 推进规则

1. 顺序完成阶段，完成项必须有代码或测试证据；不能仅因文档已写就标记完成。
2. 每轮先检查现有改动，只修改当前阶段涉及文件。
3. 测试使用独立临时目录，不覆盖日常 `.data`、配置或登录数据。
4. 每完成一个阶段更新本文件的状态、验收记录、遗留事项和下一步。
5. 数据库选型、第三方账号接入、正式签名等需要外部信息时单独确认，不编造凭据。
