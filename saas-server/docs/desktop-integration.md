# SaaS 与桌面基座接入

SaaS 是独立项目，可在没有桌面项目的机器上安装、测试和部署。服务端指纹生成、校验、加密存储与加密响应都由 `src/` 内的模块完成，不从桌面源码导入函数，也不在部署时复制桌面文件。

网页业务接入由 `public/desktop-sdk.js` 负责：将通用 `window.desktopBridge` 包装为当前业务使用的 `window.workspaceBridge`，自行完成登录态、CSRF、团队和环境启动请求。客户端不读取 SaaS Cookie，不知道业务接口路径或数据库配置。

`src/desktop-protocol.js` 独立实现公开的 `desktop-launch-v1` JSON 加密协议；服务端仍兼容已发行 0.1.1 客户端的旧加密消息。普通浏览器没有通用桥接时保持网页模式，不能伪造桌面环境已启动。

从旧版本升级时，先部署兼容旧加密消息的新 SaaS，再分发 0.2.0 基座。旧客户端继续使用旧桥接；新客户端由网页 SDK 接入新协议，双方可分别升级和回滚。

开发、测试、生产页面地址由部署者提供给基座使用者配置，双方无需放在同一源码目录。更新清单可以由独立发布服务或静态站点提供；本项目的更新文件接口只是可选实现，不是基座启动条件。

0.3.0 授权链使用 platform-runtime-v2，正式凭据进入 auth_accounts；Platform 与 RPA 由客户端动态加载、启动检查并本地缓存。能力文件在系统管理后台上传和自动编号，网页不参与更新。详见[客户端授权重构](../../docs/客户端授权重构.md)。

首次将 `.env.example` 复制为目标环境文件，填写 MySQL、邮件等真实配置。升级保留原 `.env.*`、数据库及数据目录 `encryption.key`；业务参数和私钥不进入源码包。`npm test` 只依赖本项目、MySQL 与测试自带的本机 SMTP，不需要 Electron。

历史业务页面保存在 `archive/`，不作为当前部署内容。产品设计文档归档在上层文档目录，不进入桌面基座源码发布物。
